A7 PRICING AND TIERS · DESIGN 2 OF 15 · PAPER PACK · THE LIBRARY'S ONE TABLE

Table

Benefits as rows, tiers as columns, prices and actions in the head. A6·12 handed comparison to A7 and this is the design that takes it — the only real <table> in the library so far, the only design that scrolls, and the only one that accepts a fourth tier. It also has a problem the other fourteen do not: Ghost's benefits are per-tier strings and a matrix needs shared rows. The rule that reconciles them is below, and it is invented.

The rows are the union of every tier's benefits, and the ticks fill rightwards. Ghost stores benefits as a list of strings per tier with nothing shared between them, so a matrix has to be derived: each string becomes a row when it first appears, the tier that introduced it is ticked, and every more expensive tier is ticked too, on the stated assumption that Ghost's paid tiers are cumulative. A line that names another tier — “Everything in Free” — is read as that inheritance rather than drawn as a row, which is what keeps nine rows from being eleven. Both rules are invented and both are flagged; the sidebar states them where a site can see the consequence, and the editor names 1 Cards for a site whose tiers are not cumulative.
The recommended column is a continuous plane from the head to the last row, one step to surface with a hairline on three sides and the pack radius top and bottom — the badge and the accent action are settlement 2's other two signals, unchanged. Column heads carry name, price and action; the tier description is the one field this design drops, because nine rows say what a sentence would.

ROWS TINTED · the hover surface on alternate rows, and the hairlines go · never both

No red, no crosses and no colour in a cell at any value. A matrix that marks absence in red is a section telling a reader what they cannot have, and the tick's own colour is text-muted rather than the accent for the reason A6·11 gave: twenty-seven accent ticks beside one accent button is the accent spent twenty-eight times. Rows Tinted drops the hairlines — a tint and a rule doing the same work is two edges per row — and the recommended column's plane sits above both.

1 · A real <table> with <thead>, <tbody> and <th scope="col"> per tier, named by aria-labelledby pointing at the section's h2 rather than a caption, so the name is written once. The tier name in a column head is plain text, not an <h3> — the one design in A7 where it is not, because a heading inside a cell gives a screen reader two competing structures. The badge sits in the same cell as text. 2 · Each benefit is a <th scope="row">, so a cell announces as “Reader, the archive since 2019, included”. No role="presentation" anywhere — this table is data and it is the reason the design exists. 3 · A cell holds an aria-hidden glyph and a visually-hidden word: “Included”, or “Not included” at Check and dash. At Check and blank an empty cell stays empty in the accessibility tree too — a blank cell in a table whose rows are all “included” statements reads correctly as absence, and inventing “Not included” for a cell the site left blank would be putting words in its mouth. The dash value is for a site that wants the word said. Scrolling. Below 1081 the table scrolls sideways in a tabindex="0" container with an accessible name and a visible focus ring, the row-name column pinned with position:sticky. Sticky is a position, not a behaviour — nothing is remembered and no state changes — which is why A7 still has two behaviours and this is not one of them. Contrast · row names 12.1:1 · ticks 5.4:1 · prices 12.1:1 · badge 12.8:1 · accent label 4.6:1 · the recommended column's plane against the ground 1.1:1, which is why the plane never carries the recommendation alone. At 200% text the row names wrap and the rows grow; nothing truncates and no cell scrolls inside itself.

At ≤ 767 the table is not a table. Nine rows and three columns on a 350 px column is a matrix a reader compares by scrolling, which is not comparing, so the design hands off to 1 Cards' single column and every row a tier includes is drawn inside that tier's card — the tick list is the matrix, read down instead of across. At Check and dash the excluded rows are drawn too, muted, so the comparison survives; at Check and blank they are simply absent and the card is 1 Cards' card exactly. The second frame is cut off at the second card for the crop — the third is drawn identically below it.

Content fields · data As 1 Cards, with one field dropped: the tier description is not drawn — nine rows say what a sentence would — and it is kept for the designs that draw it.
The rows are derived, and this is the category's one derivation: the union of every tier's benefits[], in tier order, each row ticked from the tier that introduced it rightwards, on the stated assumption that paid tiers are cumulative. A benefit whose text names another tier is read as that inheritance rather than drawn as a row. Both rules are invented. Where a site's tiers are not cumulative the editor names 1 Cards, whose lists are per tier and need no matching.
This is the one design that accepts four or more tiers: they add scroll distance and nothing else.
Controls · the arrangement Padding: Compact 64 · Comfortable 96 · Spacious 132. Ground: Background · Surface. Billing period: Monthly · Yearly · Both. Title size: Medium 34 · Large 40 · Display 48. Row marks: Check and blank · Check and dash. Rows: Hairlines · Tinted alternate.
The arrangement: a 384 px row-name column and three tier columns of 304 on the 1,296 content width; cell padding 14 fixed; prices Medium 40; the head carrying name, price and action. The recommended column is one continuous plane from the head's top to the last row, hairline on three sides, the pack radius at both ends. Ticks are text-muted, never the accent and never red.
Responsive · empty Responsive: above 1081 the table fits the content width. At 1080 and below it scrolls sideways — 260 for the pinned name column, 200 a tier — in a focusable, named container with a fade at the right edge; padding 80, prices 30, cells 13. At ≤ 767 the design hands off to 1 Cards' single column, every included row drawn in its tier's card; at Check and dash the excluded rows are drawn muted so the comparison survives.
Empty: no benefits anywhere → there is no table, and the editor names 1 Cards or 8 Slim Row. One tier → a matrix of one column is a list, so the design hands off to 6 Single Tier. No recommendation → no plane, no badge, every action filled.
a11y · flagged a11y: a real <table> named by aria-labelledby from the section's h2, <th scope="col"> per tier and <th scope="row"> per benefit. The tier name in a head is plain text, not an h3 — the only design in A7 where that holds. A cell is an aria-hidden glyph plus a visually-hidden “Included”; a blank cell stays blank in the tree. The scroll container is tabindex="0" with a name and a focus ring; sticky is a position, not a behaviour. No role="presentation", no structured data.
Flagged as mine: the cumulative-tier assumption and the inheritance-line rule, dropping the description, the continuous column plane, the tick's muted colour, the two row-mark values and the blank cell's silence, Rows Tinted dropping the hairlines, the dark tint stepping down instead of up, the 1080 scroll with a pinned column, the ≤ 767 hand-off to 1 Cards, and this being the one design that takes a fourth tier.
