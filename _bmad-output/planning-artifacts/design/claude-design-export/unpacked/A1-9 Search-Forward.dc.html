Search-Forward

A field, not an icon. For an archive deep enough that readers arrive looking for something specific, the search box earns permanent space between the nav and the actions — and once it is always visible, it has to behave: suggestions, recent queries, and a result list that opens without leaving the page.

Results are aligned to the field, not to the page, and never wider than it — the panel is the field’s continuation. At 390 the field keeps its second row in the bar — this is the one design where search survives the drawer collapse, because removing it would remove the design. In the drawer the field is focused on open and results push the nav list down rather than replacing it, so a reader who opened the drawer to browse is never stranded in a search they did not start.

ACCESSIBILITY · a combobox in a header
1It is a search landmark, not a nav one. The field sits in its own search region inside the header, with a real label reading “Search this site” — visually hidden, because the placeholder carries the archive size instead and a placeholder is not a label.
2Suggestions are announced. Combobox semantics: aria-expanded on the field, aria-activedescendant for the arrow-key selection, and a polite live region reporting “3 results” — the count is spoken, not just drawn.
3Escape has two steps, never three. First Escape closes the panel and keeps the query; second clears the field. Focus stays in the field throughout, and the page behind never scrolls or steals it.
4Result rows are links, one line of meta each. Each row’s accessible name is title plus section, author and date, in that order. The dimmed page behind is a visual scrim only — it is not inert, because this is not a modal.
5The field's 40 px is 44 px in practice. The hit area extends 2 px above and below the visible border, and the clear button is a 44 px target with the name “Clear search”. Focus order is logo → nav → search → actions at every width, including the two-tier tablet layout.
SPEC · A1·9 SEARCH-FORWARD · full text in “A1 Headers — Spec.md”
Content fields Shared A1 list plus searchPlaceholder (text, opt, ≤ 40 chars, defaults to “Search N essays and interviews” with the live post count). searchEnabled is not a field here — it is forced on, and the sidebar says so. Uses 4 nav items, children two deep, signInLabel, cta pair.
Data Queries run against Ghost’s content: title, excerpt and tag, debounced 200 ms, minimum 3 characters, 5 rows maximum with a “See all results” row to the A23 surface. Recent queries are local to the reader’s browser and never shown to a first-time visitor — the panel then opens with the site’s three most-read posts instead. 0 results → one line, “No matches for ‘…’ — try a tag”, plus the tag list.
Responsive · empty · a11y ≥ 1024 one row, field takes the slack, 240 px minimum. 768–1023 field moves to a full-width second row; nav, actions and placeholder all unchanged. ≤ 767 the field keeps its second row in the bar and is focused on open in the drawer, where results push the nav list down rather than replacing it. Empty: a site with under 20 posts gets a plain “Search” placeholder — quoting the count would undersell it. a11y: see the annotated frame — search landmark, combobox semantics, two-step Escape, spoken result count.
