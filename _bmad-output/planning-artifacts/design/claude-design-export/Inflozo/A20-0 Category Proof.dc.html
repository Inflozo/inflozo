A20 · Tag Collections

Fifteen ways to draw a set the user does not own. A tag collection binds live Ghost tags — the author writes posts, Ghost derives the tags, and the section shows some or all of them with a count and a way in. The only Add in this category is Hand-picked, which adds references to Ghost’s tags rather than tags ⚑, and nothing in it styles one tag differently from its neighbours.

What the fifteen vary is arrangement: pills, tiles, cards, rows, columns, a table, a track, a box, a band, a bar and a line. What they share is one field list, one query panel, one pill, one plate and one set of answers to the four questions §8 asks — which fields a tag card carries, what happens to a tag with no posts, what happens to a long name and an internal tag, and where every one of these links goes.

THE FOUR SETTLEMENTS · §8 · EVERY ANSWER HERE IS INVENTED AND IS FLAGGED HERE AND ON EVERY FRAME THAT DRAWS IT ⚑
1 · The tag card, and what is optional. Ghost guarantees a tag name, slug and url. Everything else is optional and most sites leave it empty ⚑: description is written by perhaps one site in five, feature_image by fewer. count.posts is derived and costs an include on the query ⚑. So A20 treats name and count as the card, description as an enhancement three designs read (3, 4, 11), and a picture as an enhancement four read (2, 4, 9, 13). Every design that reads an optional field states what it draws without it, and no design fails when both are absent.2 · Tags with no posts. Ghost returns them; A20 hides them by default ⚑ through the Tags block's Tags with no posts field, because a chip that leads to an empty archive is a dead end the reader pays for. 7 Index is the design that most wants them shown — an index that omits a topic is broken — and it still defaults to Hide. At Show they draw muted and still link ⚑.
3 · Long names, and internal tags. Internal #hash tags are never drawn anywhere in A20 ⚑ — the query filters on visibility:public, so they are not fetched rather than hidden, and there is no control to reveal them. Long names are never clamped, never ellipsised and never auto-fitted ⚑: they wrap, the row or cell grows, and the count holds the first baseline. The stress frame below is 43 characters and is drawn at every width. A26 made the same call for tag pills in a post footer.4 · Zero, one, many, and where the links go. Zero public tags removes the section entirely ⚑ in all fifteen; the editor draws a dashed placeholder naming why. One tag is drawn as one tag in fourteen of the fifteen — no widening, no centring, no stretching — and 12 Panel is the one design that hands off ⚑, to 1 Chips, below four. Every tag name is a link to that tag's Ghost archive ⚑, which is A29 Archive Headers' page and is not yet designed; the all-topics link points at a site tag index Ghost does not provide ⚑ — A26's finding 5, met a second time and now recorded as finding 1 below.

FINDINGS FOR THE ARCHITECT · EIGHT · FIVE ARE PLATFORM FACTS RATHER THAN DESIGN GAPS
1 · Ghost has no canonical all-tags route. Eight designs draw an "All topics" link and every one of them points at a page the theme has to invent — usually a custom page-tags.hbs or a static page an author maintains by hand. A26 raised this as its finding 5; A20 is the second category to meet it and will not be the last. The product should decide the route once, and A20's linkUrl should then default to it rather than being an authored URL ⚑.2 · A tag image has no alt text. Ghost gives a tag feature_image and no feature_image_alt. Designs 2, 9 and 13 draw pictures at up to 636 × 424 with alt="" and let the name carry the link. That is correct and it is also a loss — a topic's picture is often the most informative thing on the frame. If the product wants it described, it needs a field Ghost does not have ⚑.3 · Tabular figures are a pack requirement A20 cannot state. 4 Rows and 11 Ledger align counts in a right-hand column; a pack whose body font lacks tabular numerals draws a column that does not line up. This is the third time the library has needed it — A17·10 Ledger and A26·14 both raised it — and there is still no pack token for it ⚑.4 · count.posts is not free. It requires include="count.posts" on every query, which is an extra aggregate per tag. Fourteen designs read it, so A20 compiles two query shapes — with and without the include, decided by the Counts control ⚑. Someone should confirm Ghost caches the aggregate before a site with 200 tags puts 7 Index on its home page.
5 · Contrast over a photograph cannot be guaranteed. 13 Overlay sets white type over a fixed warm scrim. Against the darkest picture tested it is 4.9:1; against a bright one it is not, and no theme can measure a reader's image at build time. The fixed scrim is the mitigation, not the solution; the alternative is a plate-only design, which is 2 Tiles ⚑. Flagged as a known limit rather than solved.6 · A sticky filter bar has no module. 15 Filter Bar wants to follow the reader down a long tag archive and cannot: the registry's closest entry is header-scroll, which belongs to A1's site header and shrinks it. The sticky was cut rather than renamed ⚑. If sticky section behaviour is wanted anywhere in the library, it needs a registry decision, not a design one.7 · A20 links into A29 Archive Headers, which is not yet drawn. Every name in all fifteen designs is a link to a tag archive, and the archive's own head — its title, its count, its description, its picture — is A29's. A20 assumes an archive page exists, is public, and repeats the tag's name ⚑. If A29 decides otherwise, the counts drawn here and the counts drawn there have to agree, and this category is where the reader forms the expectation.Two things A20 settled that the next tag-bearing category should reuse rather than re-decide: the tag plate carrying the tag's own name ⚑, and hiding zero-post tags by default ⚑.8 · A tag’s colour is now read, and Ghost does not validate it. ⚑ accent_color is a free hex a site owner types. A20 derives its on-colour rather than trusting a pair, but a near-page-coloured tag will produce an invisible chip edge and there is nowhere in Ghost to warn about it. The product should decide whether the editor validates tag colours or the theme floors them.
