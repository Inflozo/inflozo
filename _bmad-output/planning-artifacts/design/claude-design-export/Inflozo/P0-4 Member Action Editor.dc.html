P0·4 · Member-aware action editor

One action, three audiences. Per action, a compact three-state editor — Logged out · Free member · Paid member — each state carrying Show (toggle), Label (text) and Link (the P0·1 Link Picker, Portal actions first). The canvas previews it through the existing member-state toggle: View as Anonymous / Free / Paid.

This is distinct from the Member visibility control that CTA-bearing sections already carry — that hides a whole section; this edits one action. Both are drawn in one frame below so the difference is legible.

The editor is per action, and an action is one slot in the section — the A1 ghost action and primary button each get their own card. Portal targets render as "Portal · Name" with the raw action in mono, because Portal actions are the first group in the Link Picker for these slots. Show off for a state removes the action for that audience server-side; siblings shift per the section's own empty rule — never a reserved gap, never a client-side flash.

Two controls, two scopes, one panel — Member visibility is a section control tagged SECTION; the action editor is tagged ONE ACTION and sits under it. When visibility already excludes an audience, the action editor's rows for that audience collapse to a note instead of editable fields — the design refuses to collect copy no reader can see. In the editor, an audience-hidden section ghosts to 40% with a pill under View as, so the page's true shape for that reader stays visible without pretending the section is gone from the project.

Two separate facts, both stated in the panel. A member ask can be impossible because of how the site is configured — self-signup off, no payment provider — in which case the action does not render at all. And an ask that does render still opens Portal, which is JavaScript. The form case is worse than a dead button, so it gets a designed notice at the same height; the button case gets a sentence in the panel where the author can see it.
