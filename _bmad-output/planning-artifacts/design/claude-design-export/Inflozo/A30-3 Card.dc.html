WHAT THE SEVEN STATES SETTLE FOR THE WHOLE CATEGORY
Sign-in is the signup page with one field and no tiers ⚑ — same measure, same button, same note. A publication that themes custom-signup.hbs gets custom-signin.hbs for free, which is why the two are one design and not two.Sent replaces the field; it never disables it. A disabled field with a message under it reads as a failure. The panel carries “Send another link” and the address is echoed so a mistyped one is visible ⚑. Expired is read from the query string (?action=signin&success=false) and is therefore JS-only ⚑; without JavaScript the reader gets the plain form, which is the same recovery in one step fewer.A signed-in member never sees a signup form ⚑. The signup route draws the membership summary and two actions instead. Invalid is the browser’s constraint first — type="email" — then Ghost’s reply; the theme draws the wording and never validates a domain itself.

The states are the card’s contents, not the card ⚑. Its width and padding never change; sent, expired and signed-in each replace the field block inside the same plane. The sent panel drops its own border inside the card ⚑ — a box inside a box is one border too many, so on this ground it is the plate colour alone.

EDITING · THE P0 PRIMITIVESEvery authored string edits inline on canvas with the P0·1 toolbar — bold · italic · underline · link, its popover carrying Open in new tab and rel nofollow · noreferrer · sponsored: eyebrow, heading, blurb, ctaLabel, note, legal, benefits[] and every state string. Ghost-owned content is never inline-editable ⚑ — the member's name and email, the tier name, the price, the renewal date, the newsletter names and a tier's description and benefits all answer "Edit in Ghost" or show P0·1's lock pill. Every URL field opens the Ghost-aware Link Picker, Portal actions first. No fixed English visitor-facing string ships: the rescued literals above are fields with defaults, and the badge vocabulary and sending word are catalog strings. There is no Preview control in this panel and there never was one to remove — states are P0·6's switcher, audiences are View as.benefits[] is the P0·3 authored list ⚑ — drag to reorder, per-row overflow with Duplicate and Remove, Add arrives with content rather than an empty shell, Remove is never disabled, and the range line reads 0–6 · 4 used. Add disables at six with its reason in a sentence. Per-item content only: a name and a detail edit inline, and no per-item layout control exists ⚑. Tiers are the other list and are Ghost’s — no Add, no Remove, no drag.The one icon slot is the primary button’s ⚑ — P0·2's button-icon rules: Before or After the label, always Small, always the label's colour, its Size and Colour rows hidden. The list marker is the second where a design draws ticks, and it is whole-list.Member Visibility lands nowhere in A30 ⚑, and it is a judgement rather than an omission: the route is the member state. A signed-in member never sees a signup form — the Data group's "A signed-in member on this page" decides what they see instead — so a section-level Everyone / Logged out / Free / Paid row would hide a page from readers the route has already sorted. P0·4’s member-aware action editor never opens here for the same reason. Recorded in the Reconciliation notes.
