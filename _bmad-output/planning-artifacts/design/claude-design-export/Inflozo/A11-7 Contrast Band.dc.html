Contrast Band

A11·1 Row inverted onto the contrast token. In every other category this design is the tokenisation claim at its hardest; in A11 it is harder than that, because a band is a ground the artwork was not made for and the theme cannot re-colour the artwork.

It produced the category's sharpest finding, and it amends A11-0's settlement 3: logoDark is not a dark-mode file, it is a dark-ground file. This band reads it in light mode, where the ground is #232019 — and in dark mode, where Paper's contrast is a pale #EDE7DA, it reads the light file instead. The band always wants the opposite file from the mode it is in.

This is the amendment A11-7 forces on settlement 3. A11-0 states the plate as a dark-mode fallback; the rule is actually about the ground, not the mode — the theme asks whether the ground behind the logo is dark, and on this band the answer is yes in light mode and no in dark. Settlement 3 is restated in A11-0's amendments in these words. So the editor's advice changes in this design only: instead of “upload a dark version for dark mode”, the field reads “this band needs the version for a dark background, which your site will use in light mode too”. A site that never turns dark mode on still needs the second file here. ⚑ Mine, and the reason this design's panel carries a line no other panel does. In dark mode the band inverts and so does the requirement. Paper's dark contrast is #EDE7DA carrying #171511 — a pale band on a deep page — so the band draws the light file, and a logo missing its light file is impossible, because logo is required. The band can therefore never need a plate in dark mode, which is the one asymmetry in the category.

ACCESSIBILITY · ONE TOKEN PAIR, AND AN ACCENT THAT CANNOT BE USED The accent fails on the band in both modes and is substituted rather than adjusted. #D96C3F on #232019 is 2.3:1, so the link's underline and the focus ring take the carried colour — 15.9:1 and 14.1:1 — and the section spends no accent pixel at any setting. A11's floor says the accent lives in two places; this design is the one where it lives in none. A10·7's position, verbatim. Structure is 1 Row's exactly: <section aria-labelledby>, an <h2>, a <ul> of <li>, an <img> with a required alt in each. The band is a background-color on the section, not a wrapper element, so switching between this design and 1 Row changes nothing a screen reader can detect — which is the tokenisation claim stated as an accessibility fact. The <picture> query is inverted in this design and only in this design. Elsewhere the dark source is prefers-color-scheme: dark; on the band the dark-ground file is the light-scheme source. The alt is on the single <img> underneath either way, so the announcement is identical in both modes and identical to every other design's. ⚑ Mine. Contrast on the band: title 15.5:1 light / 14.8:1 dark, muted at 72% in light 8.6:1 and at 70% in dark 6.1:1, link and ring 15.5:1 / 14.8:1, the derived hover surface 1.3:1 / 1.4:1 and decorative. A logo takes no ratio, and on this band the editor's 3:1 advice is against the band's colour rather than the page's — which the field says in this design only. In forced colours the band loses its fill and the section reads as the ordinary page. That is correct and it is stated: the band carries no information, and the wall it holds is the same wall. Reduced motion changes nothing. Print drops the band — and with it the inversion, so print draws the light files, which is the one place printing changes which file is used.
