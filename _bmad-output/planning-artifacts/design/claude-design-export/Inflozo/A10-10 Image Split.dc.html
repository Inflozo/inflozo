Image Split

A photograph on one half and everything else on the other. The head sits in the column with the stats rather than above both halves, which is what separates this from A9·10 and from 6 Split Head: the text column holds an eyebrow, a title, a sub, four numbers, the source line and the link, and the photograph sits beside all of it.

The photograph is the reason to pick this design and the reason it is hard to size. A row of numbers is short and a portrait crop is tall, so the two columns are rarely the same height — and A10 equalises nothing. Both columns are top-aligned, the taller one sets the section's height, and the crop control says which crop matches which count. With no image authored the section draws 1 Row.

Image side Left or Right is a row reversal and it moves the photograph in the DOM, so at Left it is read before the numbers and at Right after them. Neither order is wrong and the panel states which one is drawn — A9·10's disclosure, and the one place in A10 where authored order is not drawn order. The image is not a link, has no hover state, and does not move. No zoom, no parallax, no lightbox: A14 Galleries owns anything a reader opens. With no image authored the section draws 1 Row and the panel reads “No image. Drawing 1 Row.” — a half-width column of four numbers beside empty ground is a broken section rather than a plainer one. With an image and one stat the section draws 4 Single, and the photograph is dropped. That is the loudest hand-off in the category and it is stated: 4 Single has no image, so a site that wants both keeps two stats.

ACCESSIBILITY · ANNOTATED · A PHOTOGRAPH, FOUR NUMBERS AND ONE LINK The photograph is an <img> inside a <figure>, its alt text from imageAlt. With no alt authored it takes alt="" and is announced as nothing, which is correct for a photograph that illustrates numbers stated in the text. The editor asks for alt text and does not block saving without it, and the panel says the image is decorative until it is described. ⚑ Mine. The <figcaption> on these frames is a canvas annotation and is not part of the section. A10 draws no caption under any image: the label under each number is the section's only explanatory text. ⚑ Mine, and stated because a figure with no caption is unusual enough to look like an omission. The two halves are a flex row and not two landmarks — no <aside>, no nested <section>, one <h2> naming the whole. The stats are a <ul> of <li>, each a <p> holding value and label, so the four announce as four items and not as eight fragments. Image side changes DOM order and reading order together, which is why it is disclosed rather than treated as a visual switch. There is no order property anywhere in the design: what is read is what is drawn, at every width. Contrast: value 15.8:1 light / 15.1:1 dark, label and source 5.6:1 / 6.0:1, link underline 3.3:1 / 6.3:1, eyebrow 5.6:1 / 6.0:1. No motion: the image does not fade in, the numbers do not count up, and nothing runs on scroll. One tab stop, on the link. Print keeps the photograph and stacks the halves, image first, at the printer's own width.

STATS · the item list · outside the design’s listStats is the P0·3 item list: Add stat arrives with content — value 100, label “What this number counts” — Remove is never disabled, drag to reorder, per-item content only. Per item: value ≤ 12 · prefix ≤ 3 · suffix ≤ 6 · label ≤ 60. note, prev and share held, and the image and its alt text are section fields, not item fields — there is no per-stat image anywhere in A10. Value source: Authored · Member count · Paid member count. At Member count the value renders Ghost’s {​{total_members}} string verbatim — “1,200+” in, “1,200+” out, no maths and no formatter, which is the category’s own no-formatter rule — prefix and suffix are disabled and the label stays authored. {​{total_paid_members}} is offered only when the site has paid members enabled. Eight is the ceiling of stats[], raised from six in this pass: “Eight numbers is as many as a reader holds in one look. A ninth is a table, and a table is a different section.” 3 Grid is the only design that draws eight; everywhere else seven or eight authored names it. Seven or eight authored → 3 Grid, and the photograph is dropped; the panel states that before the frame changes.
EDITING · the P0 primitivesValue, prefix, suffix and label edit inline on canvas, selected where they are drawn rather than only in the repeater. The value raises no marks toolbar — it is plain text, so bold, italic and a link inside a figure are withheld rather than offered and refused. Eyebrow, title, sub, source and the link label take the P0·1 toolbar — bold · italic · underline · link, the popover carrying open-in-new-tab and rel nofollow · noreferrer · sponsored. A value bound to a member count is not inline-editable: clicking it says “Edit in Ghost”, because the figure is the site’s member list and not a word anyone typed here. The image opens the Image Picker, whose popover carries Image focus: Centre · Top · Bottom — reachable beside Crop, never a hidden field — and asks for alt text on drop. sourceUrl and linkUrl open the Link Picker; the section link takes an optional P0·2 icon.
BEHAVIOUR · from the fixed registrycount-up, from the fixed registry, and only at Count up On. Its own degradation is the argument: “The final value renders as static text — it is already in the HTML before JS ever runs.” JS off, reduced motion and assistive technology all get the figure rather than the animation, and the module does not re-run on the way back up the page. Edit-safe: it does not run while the section is edited, so every frame here is still a resting state. At Count up Off — the default — this design declares no module at all: the halves are a flex row, Crop is an aspect ratio, Image side changes DOM order rather than setting order, and the photograph is a plain — an attribute, not a module.
DATA · Ghost’s two member helpers · outside the design’s listTwo figures in A10 can come from Ghost, and both are public theme helpers: {​{total_members}} and {​{total_paid_members}}, each rendering a pre-rounded string. They are reached from the item’s Value source and not from a “Populate from…” panel — there is no list to populate. Everything else is authored in this section.
