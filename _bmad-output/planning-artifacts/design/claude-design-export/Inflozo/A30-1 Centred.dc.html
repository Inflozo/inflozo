WHAT THE SEVEN STATES SETTLE FOR THE WHOLE CATEGORY
Sign-in is the signup page with one field and no tiers ⚑ — same measure, same button, same note. A publication that themes custom-signup.hbs gets custom-signin.hbs for free, which is why the two are one design and not two.Sent replaces the field; it never disables it. A disabled field with a message under it reads as a failure. The panel carries “Send another link” and the address is echoed so a mistyped one is visible ⚑. Expired is read from the query string (?action=signin&success=false) and is therefore JS-only ⚑; without JavaScript the reader gets the plain form, which is the same recovery in one step fewer.A signed-in member never sees a signup form ⚑. The signup route draws the membership summary and two actions instead. Invalid is the browser’s constraint first — type="email" — then Ghost’s reply; the theme draws the wording and never validates a domain itself.

Seven states, one geometry. The field never moves and the column never changes width — every state is a swap inside the same 480 measure ⚑. Sent replaces the field with a panel on the page’s plate colour, carrying the address back and a “Send another link” button; the field is replaced, not disabled ⚑.

THE DATA GROUP · THE MEMBERSHIP SOURCE, RECUT · IDENTICAL IN ALL THIRTEEN · NOT COUNTED
Which page this is
Signup🔒
Read-only. The template decides — the section reports whether it is drawing custom-signup, custom-signin or custom-account ⚑, and draws the matching arrangement.
Form wiring
data-members-form🔒
Read-only, new in this pass ⚑. The form carries data-members-form="signup" or "signin" and the drawn states are Ghost's own: Ghost writes loading, success and error onto the form element, which are sending, sent and invalid ⚑. Expired stays the query string's and already-signed-in is server-side. The sign-out button carries data-members-signout ⚑ — Ghost's only sign-out mechanism, and the answer to the "verify the attribute" note the frames carried.
Tiers
From Ghost, visible only▾
From Ghost, visible only · From Ghost, all · Off. Reads {​{#get "tiers"}​}; the user cannot add or remove a tier here ⚑ — tiers are Ghost objects and are edited in Ghost.
After the address is sent
Sent panel in place▾
Sent panel in place · Portal takes over. In place is the default ⚑ — the themed page keeps the reader where they were; Portal's own notification is the alternative.
One-time code entry
Off▾
Off (default) · On, new in this pass ⚑. Ghost's magic-link email now carries a sign-in code as well as a link and the themed sent panel said only "check your email". At On the sent panel adds a code field and its own button, under the sentHeading text. ARCHITECT: member-form registry extension, and an endpoint to verify the code against ⚑ — no module in the registry verifies a code today. No-JS: the field is absent from the DOM and the emailed link still works.
A signed-in member on this page
Membership summary▾
Membership summary · Send them to the account page. Never the signup form ⚑ — a member who lands on /signup/ has nothing to sign up for. This is the category’s member-state model, and the reason no design carries a Member visibility row ⚑.
Everything that changes a subscription

Read-only. Plan changes, checkout, billing, email changes and newsletter preferences are Portal’s ⚑ — the theme draws the trigger and Portal draws the rest. This is the category’s boundary and no control moves it.

Ghost-owned content is never inline-editable ⚑ — the member's name and email, the tier name, the price, the renewal date, the newsletter names and a tier's description and benefits all answer "Edit in Ghost" or show P0·1's lock pill. Every URL field opens the Ghost-aware Link Picker, Portal actions first.
