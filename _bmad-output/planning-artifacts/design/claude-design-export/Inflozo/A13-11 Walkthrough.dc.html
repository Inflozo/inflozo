Module: tabs. JS off, quoted from the registry: “All panels render stacked and visible, each preceded by its tab label as a heading.” Nothing is lost — six titles, six labels, six bodies and six pictures, in authored order, in one column. It is a complete degradation and it is closer to 3 Rows than to this design. ⚠ The finding: the heading level differs with and without JavaScript. With JS on there is one <h2> and the step titles are <p>s, per A13-0's step-card rule. With JS off the registry emits a heading per panel, so the page gains six <h3>s that are not in the outline when the module runs. This design therefore breaks A13-0's “a step title is never a heading” rule, and it breaks it only in the no-JS branch, which is the worst place for a rule to change. The registry's degradation is an acceptance criterion and this document's rule is that the drawn panel is the authority, so the collision is real. Either the module gains a branch that stacks without emitting headings, or A13 accepts a category-wide exception here. The architect's call, not this document's. Edit-safe. The behaviour does not run while the section is being edited, the selected tab is never persisted and resets to the first step on reload, and there is no URL fragment, no localStorage and no deep link to a step. Every frame in this file is a resting state with step 01 selected. Refused: autoplay through the steps, a progress bar, previous and next buttons, a “step 3 of 6” counter, and opening a step from the URL. The first is a slideshow of a process; the last would make a step a page, and A13 has no per-step URL.
