PASS FIVE PATCH · 3 SEPTEMBER 2026 · IMAGE FOCUS IS ONE SHARED CONTROL, DEFINED IN P0·9
What changed on this frameNothing drawn changed. This design draws no picture at any setting, so it holds no Image focus row and never held a copy of the control's values: nothing was added and nothing was removed. No control, value, default, measure, type step, colour or spacing step changed.
The rule that required itOne control name means one set of values. Image focus was never a shared control: two dozen category specs each wrote out their own copy of its values, which is that rule at its worst in the library. It is now defined once, in P0·9, carrying both axes — up and down, and side to side — and a category supplies only the slot it applies to. The side-to-side axis is the owner's ruling of 3 September 2026 and A29 did not have it.
On this designImage focus has no subject here — no row, no greyed row, no placeholder — which is P0·9's not-drawn case and what this panel already did. The Data group's Image row stays drawn disabled with its reason, as the category ruled: the field is kept, not discarded.
Ghost never sees thisFocus is a hint the compiler resolves into the crop the theme ships with: the project stores the choice, the compiler resolves it, and nothing about it reaches Ghost or comes back — which is why it is a control and not a data binding. It declares no behaviour module, so this design's no-JavaScript line is unchanged.
OPEN FOR THE OWNEROPEN FOR THE OWNER — is there a never-offered note for a design that draws no picture at all? What I would have needed to know: whether P0·9's not-drawn note — written for a design that places a photograph at its own shape — is meant to appear on a design that draws no photograph at any setting. Why it is open: this panel already draws the Data group's Image row disabled with its reason, so a second sentence about focus may be a duplicate rather than a clarification. What I did instead: left this panel exactly as found — no focus row and no note — and recorded the question.
