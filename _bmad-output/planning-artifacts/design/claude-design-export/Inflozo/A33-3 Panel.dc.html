THIS TREATMENT’S CONTROLS AND WHAT THEY SELECT
Plane and Plane width → every .kg-card except the HTML card, which has no element ⚑; the header card takes the plane’s width rather than the content column.Media on the plane → .kg-image-card, .kg-gallery-card, .kg-embed-card, .kg-video-card.The plane is the card element itself with padding, not a wrapper — the same constraint that decides the HTML card.Space around cards → the adjacent-sibling margin on .kg-card, inside the theme’s own wrapper around the post body. Every documented card carries .kg-card alongside its own class.Captions → figcaption inside .kg-image-card, .kg-gallery-card, .kg-embed-card and .kg-video-card. One trap: .kg-file-card-caption is the file card’s description, not a caption, and the caption rule must not reach it.Credit line → the trailing em run inside that same figcaption. This is the invented reading ⚑ — Ghost has no credit field — and it now carries a version risk: Ghost 6 strips em and strong from a feature-image caption while Ghost 5 keeps them (tested 2026-08-31). Whether the same stripping reaches a card’s figcaption is untested; the owner commissioned that test on 1 September 2026 and it stays open until it is run. One cost of the rule is accepted rather than solved (owner, 1 September 2026): a caption ending in italics for any other reason — a film title, a ship’s name — reads as a credit, and the Credit line control’s help text now says so in the editor’s own words.
THE WIDTH CLASSES · WHAT THE CARD WIDTHS ROW DEPENDS ON
.kg-width-wide and .kg-width-full sit on the card’s own element beside its card class — figure.kg-card.kg-image-card.kg-width-wide. These two are the whole of the width contract.Regular has no class on an image, gallery or embed figure — Ghost’s documentation says a normal-width card carries no extra class, so the regular rung is the card class’s own default and never a .kg-width-regular selector. The signup card is the exception: Ghost documents kg-width-regular on it. Do not write one rule for both.Two cards arrive with a width class already set ⚑: Ghost’s own markup ships .kg-header-card with kg-width-full, and its gallery example ships .kg-gallery-card with kg-width-wide. The signup card also provides .kg-content-wide at full width and .kg-layout-split when it carries an image.In this treatment: the plane runs to 1,040 with the content held at 720 inside it; the media stays in the measure by default.
WHERE WE ARE NOT CERTAIN · SAID RATHER THAN GUESSED ⚑
Verified against Ghost’s theme documentation: .kg-card, .kg-image-card/.kg-image, .kg-gallery-card/.kg-gallery-container/.kg-gallery-row/.kg-gallery-image, .kg-bookmark-card and its eight parts, .kg-embed-card, .kg-callout-card/.kg-callout-emoji/.kg-callout-text, .kg-toggle-card/.kg-toggle-heading/.kg-toggle-heading-text/.kg-toggle-card-icon/.kg-toggle-content, .kg-button-card/.kg-btn, .kg-file-card and its parts, .kg-audio-card, .kg-video-card, .kg-header-card, .kg-signup-card, .kg-product-card/.kg-product-card-container, .kg-width-wide, .kg-width-full.Confirmed against Ghost’s own card renderers, 3 September 2026 — read from the code that emits the classes, on both supported versions: .kg-cta-card for the call-to-action card; .kg-callout-card; .kg-product-card, whose inner classes are kg-product-title, kg-product-image, kg-product-description-wrapper and kg-product-button-wrapper; and .kg-header-card, whose Ghost 6 shape is kg-header-card-content, -heading, -subheading, -subheading-wrapper, -text, -image, plus kg-header-button-wrapper, kg-v2, kg-style-accent, kg-style-image, kg-layout-split, kg-size-large, kg-swapped, kg-align-center and kg-content-wide. All four drop their unverified mark, and each records the code it was checked against rather than the documentation.Deleted rather than corrected: the email-content card’s selector ⚑. Its renderer returns an empty container unless the render target is email, so on the web it produces no element and no class at all — the rule matched nothing, ever, and there is nothing to correct it to. The card is still drawn dashed in the roll, because an author can still insert it; what is gone is the selector.Still unverified, and still carrying no rule of its own ⚑: the eight callout colour variants beyond .kg-callout-card-accent, pattern .kg-callout-card-. The confirmation names the callout card, not its colour variant classes, so the variants stay marked rather than promoted on a reading — OPEN FOR THE OWNER in the specification’s Patch notes. A wrong selector styles nothing silently, which is the worst failure available here.The treatments target Ghost’s current card renderer only — the owner’s ruling, 3 September 2026, and a stated limitation rather than an open question. Ghost 5 ships both the current renderer and an older one, because a Ghost 5 site can still hold posts written before the current editor, and header, file, product, video and embed cards emit different classes depending which renderer produced the post — most severely the header card, whose older markup carries almost none of the structure these treatments style. In words a customer can be shown: a post written before Ghost 5’s current editor keeps Ghost’s own default card styling — readable, just not carrying the chosen treatment. Why it went that way: a second selector set would roughly double this category’s stylesheet and its testing permanently, and the header card would need genuinely different rules rather than a second selector. Ghost 5 is end-of-life, so the affected posts are a shrinking set..kg-nft-card stays unstyled, deliberately — the owner’s ruling, 3 September 2026. Ghost still ships the card and this category draws twenty cards without it; it keeps Ghost’s default appearance. Recorded as a decision rather than a gap, so no later pass raises it as an oversight.No class at all: the divider is a bare hr; markdown and HTML emit no wrapper; the public-preview cut leaves an HTML comment; the email-content card emits no element and no class on the web, so its selector is deleted rather than corrected. The toggle exposes its state as [data-kg-toggle-state="close"|"open"] — a stylesheet can read the state, but only Ghost’s script ever changes it, so with JavaScript off the card stays closed.

A33 ships a stylesheet and nothing else, so the selector is the deliverable: inside a post’s body we own the stylesheet and not the markup, the ARIA attributes or the text. Nothing here assumes markup A33 would have to emit ⚑. One build fact belongs beside these: Ghost injects its own cards.min.css through ghost_head unless the theme’s package.json excludes a card in card_assets, so a treatment’s rules only take effect for cards on that exclusion list. Settled by the owner, 1 September 2026: A33 replaces Ghost's card CSS for all twelve excludable cards — nft ignored, since this category draws no NFT card — and the theme always re-includes Ghost's own cards.min.js, so A33 owns the look and Ghost keeps the behaviour. One condition, tested first and with its fallback already written ⚑: an exclusion takes a card's assets rather than its stylesheet alone, so if the served bundle turns out to be filtered by the config, the seven static cards are excluded and toggle, gallery, audio, video and signup stay on Ghost's assets, styled by a deeper selector — excluding those five would leave a card that renders and does nothing.

WHAT DOES NOT CHANGE · THE FOUR STATES EVERY A33 DESIGN OWES
In the editor every card draws at its resting state ⚑ — the toggle closed, no hover, no ring. The treatment is CSS, so the edit-time picture and the published picture are the same. With JavaScript off fourteen of the twenty cards are identical ⚑. Six depend on scripts that are Ghost’s or the provider’s, not A33’s ⚑: the toggle’s open and close, the gallery’s row ratios, the audio and video players, the signup card’s post, and the embed’s provider markup. The registry has no module for any of them — a finding, not a design, and A33 declares core rather than inventing one. The treatment never restyles what is inside an iframe ⚑. The embed card’s frame, radius and caption are A33’s; the provider’s markup is the provider’s. No control in A33 styles one card of one post ⚑ — a value is written once, site-wide, and every card of that type reads it.

The plane does not hover ⚑ — it is a ground, and a ground that changes colour under the pointer reads as a selection. Only the bookmark’s inner column responds, and it responds by stepping to the hover token. Focus rings draw around the link, not around the plane.

TWO RECTANGLES · 32 PX OF SURFACE AROUND THE PHOTOGRAPH · OFFERED, NOT DEFAULT ⚑

Both values are legitimate and one is the default for a reason ⚑. The author’s, per card🔒

Scraped by Ghost🔒

Ghost’s own script🔒
