Tag Row

The tags as the whole footer: a small label, the tags at 44 px full-height targets at reading size rather than meta size, and one link to the archive under them.

It is the footer for a site whose tags are real navigation — a publication with fifteen sections rather than three moods. Everywhere else in A26 a tag is 13 px meta; here it is 15, 17 or 19 and it is the only thing on the page.

At Tags shown 3 a post with seven tags draws three and the "+ more" link ⚑, and the count is a link to the post itself rather than a disclosure that opens — there is no JavaScript in this design and there is not going to be. At the top of the Tags shown range the row wraps and the section grows; a post with fifteen tags is a wall of pills, which is the honest consequence of the setting.

EDITING · THE P0 PRIMITIVESInline on canvas with P0·1: tagsLabel and archiveLabel. The tag names are Ghost’s and clicking one says “Edit in Ghost” ⚑ — including the “+ more” link, which is derived. The archive URL opens the Link Picker, the only URL field in A26. P0·3’s item controls land nowhere: A26 authors no array — the tags, the authors and the two neighbours are Ghost’s, and a Ghost-sourced list never shows an Add ⚑. P0·4 and Member Visibility land on 12 Subscribe alone in this category. P0·5’s “Populate from…” panel lands nowhere — the footer reads the post’s own relations, not a query ⚑. No Preview control existed to remove; P0·6’s state switcher is how the absent blocks and the confirmations are seen while editing. No fixed English visitor-facing string ships ⚑: every authored label carries a default, and the strings nobody authors are theme translation-catalog strings.
DATA · THE POST’S OWN RELATIONS, AND NOTHING QUERIEDtags[] — name and url, never accent_color ⚑, internal #hash tags never drawn. Tags shown picks a count, never which, from Ghost’s own order, primary first — and there is no Add, because the list is Ghost’s ⚑. 0 → nothing renders; the design hides what does not apply and never turns into another design. {{#prev_post}}/{{#next_post}} are post-context only ⚑ — on a page the pair is absent, which is the category’s absent-block rule and not a new one. On a page the tag row draws normally: a page can carry tags, so this design is not post-only.

WHAT THIS PANEL SETTLESTags shown is a count, not a selection ⚑ — it takes the first N in Ghost's own tag order, which is the order the writer set in the post. There is no control that chooses which tags, here or anywhere in A26: the tags are the post's, and the section is not allowed to edit the post.The archive link's destination is the site's tag index route ⚑ — an invented default, because Ghost has no canonical "all tags" page and a theme has to pick one. It is a finding for the architect, not a decision this design should own.Cut: a tag colour ⚑ (Ghost tags carry an accent colour and this design refuses it — a row of seven colours is not a design), a post count per tag, a hash prefix, an internal-tag value.

POST FOOTERS PATCH · 30 AUGUST 2026 · WHAT CHANGED ON THIS FRAME, AND THE RULE THAT REQUIRED IT
“+N more” carries no numberThe overflow link reads “+ more”, not “+4 more”. A template cannot subtract the drawn tags from the total — it can only be told that another tag exists — so the count could only have been hard-coded. It is still a link and still not a disclosure, so the unscripted page is unchanged.
Item counts are a number pickerTags shown is a stepper, 1 to 12, default 6 — new in this pass, where the row drew Three · Six · All. The + is greyed at twelve with the reason visible: past twelve the row is four lines and stops being a gesture. The old All value is gone, which is the one thing this pass took away: a post with more than twelve tags now shows twelve and the “+ more” link. A post with fewer tags than the number draws all of them and no link.
No design ever turns into another designThe hand-off to 6 Slim is deleted in four places. An untagged post now renders nothing at all — no label, no ruled row, no reserved height — and the editor reads “This post has no tags, so this footer renders nothing. Add a tag in Ghost.” It was the only design in A26 that swapped rather than dropped, and it no longer does.
The no-JavaScript noticeNo subject in this design — it contains no subscribe and no sign-in form, so there is nothing for a designed notice to replace. The share links are real <a href> URLs and work unscripted; only the copy-link button is hidden.
Member buttons are conditionalNo subject at rest — this design draws no member action. At Blocks Everything the inherited subscribe bar carries the note, and the note is 12 Subscribe’s.
POST FOOTERS PATCH · PASS TWO · 1 SEPTEMBER 2026 · INCLUDING THE NATIVE-SHARE RULING · WHAT CHANGED ON THIS FRAME, AND THE RULE THAT REQUIRED IT
Sharing is Ghost’s own share panel, everywhereNo subject on this frame — this design draws no share block. The ruling is recorded here because Blocks Everything and the category floor both reach it: sharing anywhere in the theme is now Ghost’s own share panel, with Copy link and Email as the fallback on older Ghost.
A control switched off by another is greyed, with the reason beside itTags shown greys its + at twelve with the reason beside it — past twelve the row is four lines and stops being a gesture. An untagged post renders nothing at all: an absent block, not a greyed control.
Avatars with no photograph show initials, and the two forms are not interchangeableNo subject — this design draws no avatar and no portrait. Were one added it would take one letter, because every person in A26 comes from Ghost.
A count that picks between drawn layouts is a named set, not a number pickerTags shown stays a number picker, 1 to 12 — every value draws the same ruled row with more or fewer pills. The old All value stays gone: past twelve the row draws twelve and the “+ more” link.
A design may declare the width below which its script runsNo width is declared, because this design declares no behaviour at all. The “+ more” is a link rather than a disclosure, which keeps the unscripted row pixel-identical.
