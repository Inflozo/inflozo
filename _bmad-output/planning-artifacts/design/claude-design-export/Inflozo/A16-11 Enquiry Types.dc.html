11 · Enquiry Types

A row of enquiry types above one form, on a full-bleed surface ground. Choosing a type sets where the message goes and swaps the line under the row; the fields never change.

It looks like a tab strip and it is not one. It is a radio group in a fieldset — which is why it needs no JavaScript, posts natively, and is the one place in A16 where the honest answer to “which module?” is “none of them”.

This is a radio group, not a tablist ⚑ — a <fieldset> of <input type="radio"> with a visually-hidden legend, styled as a row of 46 px rows at the pack radius. There are no panels to switch, because every type gets the same form: the choice sets the destination and the line beneath the row, and nothing else. That is what makes it work with JavaScript off — the chosen value posts with the message like any other field. THE FINDING · WHAT THIS DESIGN NEEDED AND THE REGISTRY DOES NOT HAVE
The closest module is tabs ⚑, and it is the wrong one: its degradation is “All panels render stacked and visible, each preceded by its tab label as a heading”, and there are no panels here — one form serves every type.So this design declares member-form and nothing else ⚑. The radio row is plain HTML and needs no module at all; naming tabs would compile a behaviour that has nothing to operate on.The finding for the architect ⚑: a segmented control that writes a form value is a shape the registry has no entry for, and it is common enough — enquiry type, subject, department — to be worth one. Until then it costs nothing, because it needs no script.

The seven states with the radio row above them, because the row is part of the form ⚑ — it posts with it, and at submitting it greys with the rest of the fields. At sent the row goes with the form ⚑ and the confirmation names the type that was chosen: “Sent to Editorial.” At failed the chosen type is kept along with everything typed.

THE DELIVERY GROUP · IDENTICAL IN ALL TEN FORM DESIGNS · NOT COUNTED
Where it goes
An email addressA form service
Ghost cannot receive a form ⚑ — its theme layer has no handler. At An email address the script composes a mailto: URL out of the fields and opens the reader’s mail app ⚑; with no script the fields stay and a visible “Email us at hello@…” line sits under them ⚑. Never a <form action="mailto:…" method="post"> — browsers answer that with a blank draft or with nothing, and a form that looks posted and was not is the worst state A16 could ship ⚑. At A form service the native POST stands and the service’s own page answers.
The destination
hello@orbitweekly.com
An Inflozo project setting, promotable to a Ghost Admin custom setting (text) ⚑, so the owner can change the address without a redeploy. Validated per mode — an email address at An email address, an https URL at A form service. Until it is set the section is editor-only and the page cannot publish ⚑: the old “falls back to the site’s own address” is withdrawn — Ghost exposes no site address to a theme ⚑.

Prefill for members
OnOff
Name and email pre-filled from @member.name and @member.email when a signed-in member reads the page — server-side, in the template, with no script ⚑. A signed-out reader sees the empty form at either value. On by default ⚑ — a member the site already knows should not be asked to type their own address.
Spam · a hidden honeypot field, plus your service’s own guard. No captcha at any value ⚑ — a captcha is a third-party script and a contact form is not worth one. This is a caption under the group, not a fifth row ⚑: it was read-only, and a read-only row that looks like a control is a control that lies. The form-state copy is edited in place, not here ⚑ — sentHeading, sentText, invalidText and failedText are written on canvas through the P0·6 editor state switcher (Empty · Invalid · Sent · Failed). There is no Preview control in this panel ⚑, and there never was one to remove — previewing belongs to the editor.
ARCHITECT: REGISTRY ADDITION (contact-form)The ten form designs declared member-form and it is the wrong module ⚑ — it posts to Ghost’s members endpoint, which is not where a message goes. A contact-form module is requested and no other name is coined. The no-JS state is designed anyway: the native POST at A form service, the visible mailto: line at An email address.
This is the one design where the destination is a fallback ⚑: each enquiry carries its own address, and the row above is what a type with none posts to. The project setting still gates publishing — with no destination and a type that has no address of its own, the section is editor-only.
EDITING · the P0 primitivesEvery visible text edits inline on canvas with the P0·1 toolbar — bold · italic · underline · link, the link popover carrying Open in new tab and rel nofollow · noreferrer · sponsored: the eyebrow, the heading, the blurb, each type’s label and the line beneath it — selected on the canvas, edited in place ⚑ — the field labels, the placeholders, the button label and the consent line. The field labels and the placeholders are edited by clicking them on the canvas ⚑ — this panel holds no label boxes. Nothing drawn here is Ghost-owned ⚑, so no line carries the “Edit in Ghost” lock — A16 reads only @site.title, and only as an aria-label fallback. Every URL field opens the Ghost-aware Link Picker. Buttons accept an optional icon before or after the label from the P0·2 Icon Picker with its size / colour-role popover, off by default ⚑. No fixed English visitor-facing string ships ⚑: every type label and note, the five field labels, the five placeholders, the button label, the consent line and the four form-state strings are authored fields with defaults, and “Sending…”, “Send another message”, the failed banner’s first line, “Email us at {address}” and the honeypot’s hidden label are theme translation-catalog strings.
BEHAVIOUR · from the fixed registrymember-form was declared for the form and it is the wrong module — ARCHITECT: registry addition (contact-form), as everywhere in A16. The type row still declares nothing and needs nothing ⚑: it is a <fieldset> of radios, the checked one posts, and arrow keys move between them. The closest module is tabs and it is the wrong one ⚑ — its degradation describes panels and there are none here. That stays a finding for the architect, not a licence to name a module. The no-JS state is designed either way: the native POST at A form service, and the visible mailto: line at An email address — composed from the selected type’s own address ⚑.
DATA · Ghost’s surface, and what A16 cannot readNothing is read from Ghost’s content API ⚑ — no Show ladder, no filter, and the P0·5 “Populate from…” panel is not offered anywhere in A16 ⚑, because no design reads a Ghost list. The one Ghost value is @site.title. The destination is a project setting, not section content — see the delivery group.
