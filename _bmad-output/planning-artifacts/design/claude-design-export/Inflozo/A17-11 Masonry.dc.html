A17 POST GRIDS · DESIGN 11 OF 18 · PAPER PACK · SIX CONTROLS

Masonry

Three columns filled top to bottom, each cell's image ratio set by a diagonal through the grid: ratio index = ((row − 1) + (column − 1)) mod 3. So the first column runs Portrait, Landscape, Square; the second Landscape, Square, Portrait; the third Square, Portrait, Landscape — and no two rows line up.

The important thing about it is what it is not. This is not a true masonry layout — nothing measures its neighbours, nothing packs into gaps, and no JavaScript runs. It is three independent columns and one arithmetic rule, which produces the staggered look with plain CSS and a server-rendered DOM.

That choice costs it two things. The columns do not end level — with five posts the foot of the section is a staircase. And because the rule takes the column as an input, a post's crop changes when the column count changes, which means it changes with the viewport. Both are stated as properties rather than defended.

Three 416 columns on the 24 px gutter, each a separate list, each filled top to bottom with consecutive posts — posts 1–3 in the left column, 4–6 in the middle, 7–9 at the right. Reading order runs down a column and then down the next, which is what the DOM does too: the visual order and the source order are the same, and the mono captions name each cell's post and its row and column so the rule can be checked against the drawing.
The ratio comes from the cell's place in the grid, not from the post. Ratio index = ((row − 1) + (column − 1)) mod 3 over the cycle Portrait, Landscape, Square — a diagonal, which is why column 1 reads P·L·S, column 2 L·S·P and column 3 S·P·L. A rule that used position alone would give every row the same three ratios and stagger nothing, which is the version this design is not. ⚑ Mine.
A ratio that followed the post would need a per-post field, which A17 cannot express — and one that followed the image's own shape would need the image measured before layout, which needs JavaScript. Row and column are the only inputs available at render time.
40 px between cells within a column, against the category's 48 between rows. A column is a continuous run rather than a set of rows, and the staggered tops already do most of the work of separating one cell from the next. Post 3's plate takes the Square 1:1 its cell dictates, so an imageless post is the same shape as the cells around it rather than a shape of its own.

LANDSCAPE–PORTRAIT · TWO RATIOS, SAME DIAGONAL · COLUMNS ONE AND THREE MATCH
The diagonal is the mechanism, and the cycle length is what makes or breaks it. With three ratios over three columns every column gets every ratio, no column repeats one until its fourth cell, and no two columns run the same sequence. Both claims follow from the arithmetic rather than from the drawing. With two ratios the same diagonal makes columns one and three identical, because the shift wraps after two steps — the drawing above shows it. ⚑ The general rule, enumerated rather than guessed: two columns run the same sequence exactly when their index difference is a multiple of the cycle length. So the constraint is a ceiling, not a coprimality condition: the column count must be no greater than the cycle length. Three ratios support three columns and no more — at four columns the first and fourth are identical. Two ratios support two columns; at three they repeat, at four twice over. The two-ratio cycle is offered anyway because it is calmer, and its note says what it costs: “Two ratios alternate more gently and repeat across columns.” Refused: a random cycle. Random per-render cannot be server-rendered consistently; random-by-post-id is stable but unexplainable, and a user who cannot predict what a control does will not use it. A diagonal is predictable and inspectable — a user can count cells and know what the next one will be.

FIVE POSTS · 2 + 2 + 1 · THE THIRD COLUMN ENDS WELL ABOVE THE FIRST · THE STAIRCASE
The columns do not end level and cannot be made to. Real masonry balances column heights by measuring cells and choosing where each goes; that measurement is exactly the JavaScript this design refuses. CSS columns would balance them, but it fragments a cell across a column boundary and cannot hold a card together. So the foot is a staircase, always — measured on the primary frame the three columns end 74 px apart — and the design is composed so that it looks intended: if the tops are already staggered, an uneven foot reads as the same idea rather than as a failure. Under five posts it draws the columns it can fill, and the panel may advise 1 Three Up, disclosed at the control: “Fewer than five posts. This design needs five to stagger.” Nothing switches ⚑ 29 August 2026 — the columns draw with what they have. Four posts in three columns is 2 + 1 + 1, and at that count the diagonal has nothing to establish — it reads as three columns of different lengths rather than as a rhythm. ⚑ The threshold of five is mine. With no images anywhere in the set it draws its cells without their image boxes, and the panel may advise 9 Big Type, as A17-0 specifies for the three image-dependent designs. A column of stacked plates at three different ratios is the worst-looking thing the category can produce — the diagonal makes an absence of photography louder rather than quieter, which is the opposite of what the tag plate is for.

WHAT CYCLE MEANS FOR A DESIGN SWITCH — A QUESTION A17-0 DID NOT ANTICIPATEColumns Four is removed ⚑ — under the three-ratio cycle columns one and four run identical crop sequences, so the value drew a stagger that was not there. 3 Four Up exists and is cheaper than inventing a fourth ratio.Tag and “View all” link added; Padding retired into Vertical spacing. Cycle takes the slot every other image-bearing design gives to Image ratio, and the two are not interchangeable. Image ratio writes one value that every cell reads; Cycle writes a sequence that cells index into by row and column. Both are still one value on the section, so A17-0's rule that a control writes one value and never touches a single item holds — the section stores “Portrait–Landscape–Square”, not nine per-cell ratios. ⚑ But it breaks the spirit of rule 3, and this is the finding. Switching from 1 Three Up at Image ratio Square into this design loses nothing — both fields sit on the section — but the user's chosen Square is not honoured here, and their chosen Cycle is not honoured back there. Rule 3 says no field may have nowhere to live; these two have somewhere to live and no relationship to each other. The honest statement is that A17 has two ratio fields rather than one, and the architect should decide whether ratio and cycle are two section fields or one polymorphic one. I have specified them as two. ⚑ Columns is not a neutral control here, and its note says so: “Changing this changes which crop each post gets. Four was removed in this pass ⚑ — with three ratios, columns one and four repeat.” The diagonal takes the column as an input, so Two, Three and Four each produce a different set of crops from the same posts. No other control in A17 changes a post's crop as a side effect of changing a layout count — and it is the direct consequence of choosing a rule that stagger requires. ⚑ Columns Three is the maximum the default cycle supports, and Columns Four is where it first fails — with three ratios, columns one and four run the identical sequence, so a four-column grid has a visible repeat in it. Four columns would need a four-ratio cycle, and the Cycle control does not offer one. That is a real gap rather than a preference: either Columns Four should be removed or a fourth ratio added, and the architect should pick. I have left the value in place with its note, because removing a column count from one design in the category is a bigger inconsistency than a repeat a user can see and avoid. Columns Two is safe but weak: it staggers, and at 636 the tall crop is 795 px so one cell fills a screen. Cut: any hover or reveal treatment — a staggered grid is where reveal is most tempting, and A17-0 refuses it category-wide.
