THREE WAYS TO GIVE THE ASK AN EDGE
2 Card — surface fill, hairline, md shadow, inset. An object on the page.5 Panel — surface fill the full width of the content box. A ground, not an object.13 Boxed — a hairline and nothing else ⚑. The page shows through, so the section costs no colour at all. All three are named on each other’s panels.

The box’s height holds across all seven states ⚑, as every other A22 design’s does. The one difference a hairline makes is at invalid: the field’s 1.5 px text border sits inside a 1 px border box, and the two are deliberately different weights ⚑ so the error is legible as an error and not as the box moving.

EDITING · THE P0 PRIMITIVESEvery visible authored text edits inline on canvas with the P0·1 toolbar — bold · italic · underline · link, the link popover carrying Open in new tab and rel nofollow · noreferrer · sponsored: the eyebrow, the heading, the blurb, the button label and the note. The note is the consent line and now takes the link mark ⚑ — “…you agree to our Privacy Policy” links through the Ghost-aware Link Picker, which is what the field was missing. The five state strings are edited in the state that shows them through the P0·6 editor state switcher — Empty · Invalid · Done · Subscribed · Members off — inline, in place, never a sidebar preview row ⚑. The subscribe button takes an optional icon before or after its label from the P0·2 Icon Picker, with its size and colour-role popover. The endpoint, the Portal preferences target and the member count are Ghost’s and are never inline-editable ⚑ — clicking one says “Edit in Ghost”. Translation-catalog strings ⚑ — “Subscribing…”, “Use a different address” and the visually-hidden “Email address” label: theme catalogue, not fields.
BEHAVIOUR · MEMBER-FORM · GHOST’S FORM CONTRACTmember-form, edit-safe. The form speaks Ghost’s own contract ⚑ new in this pass: data-members-form="subscribe" on the <form>, data-members-email on the field and data-members-name when Ask for a name is on. The newsletter is chosen in the markup too ⚑ — data-members-newsletter, its value the letter’s name, not its id; errors land in a data-members-error child, which is the invalid state’s own slot. Ghost’s form creates a free member and never asks for payment ⚑ — checked against Ghost’s theme documentation, 28 August 2026. Ghost’s members script drives loading, success and error, and member-form maps those three onto the designed seven. There is no no-JavaScript floor ⚑ corrected in this pass — /members/api/send-magic-link/ refuses a plain POST, tested against both live Ghost servers, so the form is replaced by P0·4’s no-JavaScript notice at the same height: “Signing up needs JavaScript — turn it on to subscribe.” The sent, error and loading states are untouched. The ask is conditional on the connected site ⚑ — it does not render with self-signup switched off or members disabled, and a paid ask needs a payment provider connected; any button that opens Ghost’s own sign-up pop-up does nothing with JavaScript off.

PASS TWO PATCH · 1 SEPTEMBER 2026 · WHAT CHANGED ON THIS FRAME, AND THE RULE THAT REQUIRED IT · RULES ARE NAMED, NEVER NUMBERED
NO CASE OF ITS OWN, AT PANEL SIZE
No greyed row of its ownBox padding, Box width, Field width, Alignment and Social proof are independent, and the hairline never thickens at any value. Nothing on this design switches anything off, and Background role stays free — the box is an edge with no ground of its own.
THE SHAPE, WHEREVER IT OCCURS Drawn, never hidden. The unavailable value is struck, the reason is one short sentence at the control and never a tooltip, and the value the design falls back to is named. The one exception is different in kind: a control this project can never offer is not drawn at all and the panel says why — A22 claims that exception nowhere.
A control switched off by another is greyed, with the reason beside it No case of its own. No lock, no narrowing, no row accepting a value the design ignores — the plainest panel in the category on this rule as on most others.
Avatars with no photograph show initials, and the two forms are not interchangeable No subject. A22 renders no person — no author, no member avatar, no initials in sixteen designs — so neither the two-initial form nor Ghost's one-letter form has anything to draw here. Recorded rather than skipped: a list the user types gets two initials, an author Ghost supplies gets one, and the two are never mixed inside one component.
The Remove button never greys out No subject of its own. 11 Reasons owns the category's only authored list; the Ghost-sourced lists in 9, 10, 12 and 15 have no Add and no Remove at all, so there is no Remove here to grey or keep.
A count that picks between drawn layouts is a named set, not a number picker No subject. Every named-value row here picks between arrangements somebody has drawn; nothing on this design counts items, so there is no picker to convert in either direction.
A design may declare the width below which its script runs No width declared. member-form runs at every width, so there is no boundary to name — and the no-JavaScript line already describes every width, not just the narrow one.
Ghost finding · the feature-image caption renders differently on the two Ghost versions No subject. This design reads no feature-image caption. Named for a builder who adds one: Ghost 6 quietly removes <em> and <strong> from a caption while keeping links and <b>; Ghost 5 keeps everything, so a caption that leans on italics gets them on one supported version and not the other.
Ghost finding · a comment count renders nothing at all without JavaScript No subject. A22 reads no comment count, ships no comment noun and labels no number — A28 owns that surface. Named because the shape matters: Ghost writes the number in with a script and prepends it to the noun, so a catalog string is the bare noun and never contains a number; the widget renders without JavaScript and its count does not.
The work list · a feed with nothing in it shows its designed empty state No feed. Nothing on this design is read from Ghost as a list, so there is no empty feed to draw. Its own empty cases — no blurb, no note — are in the written spec and are unchanged by this pass.

No arrangement moved on this frame, no control was added, removed or renamed, and no value, default, type scale, colour pack or spacing step changed. Left alone deliberately: every count-agnostic string in this library — nothing here writes a number of designs into any copy — and P0's per-prop mark allowlist, whose wording about a mark being absent from the toolbar rather than greyed is P0's text and is neither restated nor softened by the rule above, which governs a control switched off by another control.
