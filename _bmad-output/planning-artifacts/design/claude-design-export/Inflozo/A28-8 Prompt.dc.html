8 · Prompt

For a reader who is not signed in, the section is the publication’s own invitation: a heading, the count of what they are missing, and a sign-up field that Ghost’s own script posts — with JavaScript off a designed notice stands in its place ⚑. Signed-in members get the block and no prompt at all.

It buys that with the one real cost in the category: by default a signed-out reader does not see the discussion ⚑. Ghost’s block draws its own sign-up prompt and it cannot be switched off, so a section that shows both shows two calls to action stacked. The control that allows it is in the panel, and its hint says what it does.

DESIGN PATCH PASS TWO · 1 SEPTEMBER 2026 · WHAT CHANGED ON THIS FRAME, AND WHY
The count and the widget degrade differently, so one no-JavaScript sentence cannot cover both. Tested against live Ghost servers on 31 August 2026. Without JavaScript the count renders nothing at all — no number, no word, no empty box, no element: Ghost's script creates it and writes the number in. The comments widget itself does render. This design's no-JavaScript line is rewritten below as two sentences, one for each. The count is Ghost's script, not the template's. The count's accessible label sits on the surrounding element, never on the count ⚑. A label on an element that may never exist is not a label. And the count's words are bare nouns — “comment”, “comments” — because Ghost prepends the number to them; a “%” or a {count} inside that string renders literally on the page. Checked on this frame: no count string here carries either. The count is Ghost's script, not the template's. No visitor dark-mode switch where the colour scheme is pinned ⚑. It is not drawn at all — the one case of a control this project can never offer — and the panel says why, at the Data group, as a sentence rather than a tooltip. The comments widget takes its light or dark appearance from that same pinned value and is not given a second selector of its own, which is why the Block colour row is gone and why no design passes mode=. A control switched off by another is greyed, with the reason beside it — and its one exception. Free members is greyed, not hidden. It was shown only where commenting is set to paid-members only; a control that vanishes teaches nothing, so it now stays in the panel and greys with the reason beside it — “not available while commenting is open to all members” — and never accepts a value it will not honour. A control switched off by another is greyed, with the reason beside it. The form’s own no-JavaScript notice is unchanged — “Signing up needs JavaScript — turn it on to comment.” — and is a different sentence from the count’s and from the widget’s. Three things degrade three ways on this frame. The count is Ghost's script, not the template's. What did not change. The visual language, the type scale, the colour packs, the spacing system, every measure, every control's name and values, and this design's number. One conflict is recorded rather than resolved: the 29 August pass wrote that the block does not render without JavaScript; the 31 August test says the widget does. The tested finding is carried here, what the widget renders in that state is not established by it, so the owner ruled on 1 September 2026 that the <noscript> line keeps its wording — “Comments need JavaScript.” — with one live check owed rather than a rewrite on a guess. The same ruling: the section is always drawn — heading, rules and that line — whether or not the discussion can load, which closes finding 3's standing question.
DESIGN PATCH PASS · 29 AUGUST 2026 · WHAT CHANGED ON THIS FRAME, AND WHY
The count is drawn by Ghost's own script. {​{comment_count}​} renders a placeholder that Ghost's comments script fills, so with JavaScript off there is no number at all — not a zero, nothing ⚑. This design's no-JavaScript line is rewritten in the drawn spec below, and its accessible name no longer depends on the count. The comment box's colour is a setting inside Ghost. Inflozo does not change it, so the Block colour row is gone from the Data group and no design passes mode= any more. In its place a read-only row that links to the setting in Ghost ⚑. Three rule changes and one correction. The posts natively to Ghost's members endpoint promise is withdrawn — Ghost's signup endpoint refuses a plain form submission — so the designed no-JavaScript notice replaces the form at Form: Email field, and the sent, error and loading states are untouched ⚑. Both buttons are conditional: they do not render where the connected site cannot take them (self-signup switched off, or no payment provider connected), and where they do render they open Ghost's own window — with JavaScript off, nothing happens. Member who can comment → the design is 1 Rule is deleted: the prompt hides, the block leads, and it is still 8 Prompt ⚑. And the count beside the prompt is script-drawn too, so a scriptless signed-out reader gets the prompt and no number ⚑. What did not change. The visual language, the type scale, the colour packs, the spacing system, every measure and this design's number. The sent, error and loading states on member forms still work — only the promise that they work without JavaScript was wrong.
