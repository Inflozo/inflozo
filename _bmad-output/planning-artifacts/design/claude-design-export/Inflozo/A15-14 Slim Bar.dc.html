14 · Slim Bar

One line on a surface plane: a 96 px thumbnail, the film’s title, its duration, and a watch action at the right. The film opens in the theatre; the page it interrupts is barely interrupted.

It is the section for a film that is an aside — “there is a film of this”, halfway down an article — where a 960 px frame would stop the reader for something they may not want.

FIVE CONTROLS, AND WHY
Five, not six ⚑ — there is no Aspect row. The thumbnail is 16:9 and nothing else: a 9:16 thumbnail in an 88 px bar is 50 px wide and reads as an icon.And no Plays row ⚑ — see the states. The bar has no loaded state ⚑ — it always opens the theatre, at every width, because an 88 px row has nowhere to put a player. What changed on this framePanel copy only. Where this frame enumerated Image focus’s values it now cites P0·9, which defines the control once and carries both axes — up and down, and side to side. The values are not restated here.
The rule that required itOne control name means one set of values. A private copy of a shared control’s values is the failure the rule exists to prevent, and A15 held one. Image focus is defined once, in P0·9, and it carries both axes — owner-ruled 3 September 2026, and the horizontal axis arrives with the same ruling rather than being drawn here.
Nothing was redrawnNo panel row was added or removed. Image focus has never been a row in this design’s control list — it is per film, reached from the Image Picker popover — so there was nothing on this frame to redraw, and the control count is unchanged. Ghost never sees it: the compiler resolves the hint, which is why it is a control and not a data binding.
No design total is written anywhereChecked, and nothing was added. No copy on this frame quotes a library size, in any form, and none was introduced by this pass.
