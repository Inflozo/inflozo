10 · Slim

One line of type and the block. No hairline, no plane, no box, and no ground of its own — the section takes the colour of whatever it is dropped onto, which is what makes it the design you can put inside A25·3’s sheet without a seam.

Its padding ladder is a step below the category’s: 40 · 64 · 96 rather than 64 · 96 · 132 ⚑, and it defaults to Compact. A publication that treats comments as a footnote should not have to spend 264 px saying so.

DESIGN PATCH PASS TWO · 1 SEPTEMBER 2026 · WHAT CHANGED ON THIS FRAME, AND WHY
The count and the widget degrade differently, so one no-JavaScript sentence cannot cover both. Tested against live Ghost servers on 31 August 2026. Without JavaScript the count renders nothing at all — no number, no word, no empty box, no element: Ghost's script creates it and writes the number in. The comments widget itself does render. This design's no-JavaScript line is rewritten below as two sentences, one for each. The count is Ghost's script, not the template's. The count's accessible label sits on the surrounding element, never on the count ⚑. A label on an element that may never exist is not a label. And the count's words are bare nouns — “comment”, “comments” — because Ghost prepends the number to them; a “%” or a {count} inside that string renders literally on the page. Checked on this frame: no count string here carries either. The count is Ghost's script, not the template's. No visitor dark-mode switch where the colour scheme is pinned ⚑. It is not drawn at all — the one case of a control this project can never offer — and the panel says why, at the Data group, as a sentence rather than a tooltip. The comments widget takes its light or dark appearance from that same pinned value and is not given a second selector of its own, which is why the Block colour row is gone and why no design passes mode=. A control switched off by another is greyed, with the reason beside it — and its one exception. What did not change. The visual language, the type scale, the colour packs, the spacing system, every measure, every control's name and values, and this design's number. One conflict is recorded rather than resolved: the 29 August pass wrote that the block does not render without JavaScript; the 31 August test says the widget does. The tested finding is carried here, what the widget renders in that state is not established by it, so the owner ruled on 1 September 2026 that the <noscript> line keeps its wording — “Comments need JavaScript.” — with one live check owed rather than a rewrite on a guess. The same ruling: the section is always drawn — heading, rules and that line — whether or not the discussion can load, which closes finding 3's standing question.
DESIGN PATCH PASS · 29 AUGUST 2026 · WHAT CHANGED ON THIS FRAME, AND WHY
The count is drawn by Ghost's own script. {​{comment_count}​} renders a placeholder that Ghost's comments script fills, so with JavaScript off there is no number at all — not a zero, nothing ⚑. This design's no-JavaScript line is rewritten in the drawn spec below, and its accessible name no longer depends on the count. The comment box's colour is a setting inside Ghost. Inflozo does not change it, so the Block colour row is gone from the Data group and no design passes mode= any more. In its place a read-only row that links to the setting in Ghost ⚑. At Heading: Count only the theme's whole visible text is script-drawn ⚑, so with JavaScript off this section is the <noscript> line and nothing else. The section takes aria-label="Comments" at Count only and at None — its name can never be the count. Settled: the value is called None, and the shared control gains it. Ruled by the owner on 29 August 2026. The background row offered three values and all three paint; this design's ground is one it declares and does not paint. "Inherit" is withdrawn as a word, and the shared row gains a fourth value — None: show whatever is behind — available in every category ⚑. This design's row is locked at None, with the reason shown. A28 is the first category to need it and the shared control changes library-wide, which is a finding for the architect rather than a local invention. What did not change. The visual language, the type scale, the colour packs, the spacing system, every measure and this design's number. The sent, error and loading states on member forms still work — only the promise that they work without JavaScript was wrong.
