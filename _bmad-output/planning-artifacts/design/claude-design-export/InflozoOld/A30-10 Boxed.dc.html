WHAT THE EIGHT STATES SETTLE FOR THE WHOLE CATEGORY
Sign-in is the signup page with one field and no tiers ⚑ — same measure, same button, same note.Sent replaces the field; it never disables it. The address is echoed so a mistyped one is visible ⚑ — the address the visitor typed, never a field Ghost hands the theme. Expired is read from the query string and is therefore JS-only ⚑; without JavaScript P0·4’s notice stands in the form’s place ⚑.A signed-in member never sees a signup form ⚑ — the route draws the membership summary and two actions instead.

The box holds; its middle compartment changes ⚑. The sent and expired panels are drawn without their own border inside it — the compartment is already bounded ⚑ — and the plate colour alone carries them, which is the same rule 3 Card follows for the opposite reason.

THE DATA GROUP · THE MEMBERSHIP SOURCE, RECUT · IDENTICAL IN ALL THIRTEEN · NOT COUNTED
Which page this is
Signup🔒
Read-only. The template decides — the section reports whether it is drawing custom-signup, custom-signin or custom-account ⚑, and draws the matching arrangement.
Form wiring
data-members-form🔒
Read-only, new in this pass ⚑. The form carries data-members-form="signup" or "signin" and the drawn states are Ghost's own: Ghost writes loading, success and error onto the form element, which are sending, sent and invalid ⚑. Expired stays the query string's and already-signed-in is server-side. The sign-out button carries data-members-signout ⚑ — Ghost's only sign-out mechanism, and the answer to the "verify the attribute" note the frames carried.
Tiers
From Ghost, visible only▾
From Ghost, visible only · From Ghost, all · Off. Reads {​{#get "tiers"}​}; the user cannot add or remove a tier here ⚑ — tiers are Ghost objects and are edited in Ghost.
After the address is sent
Sent panel in place▾
Sent panel in place · Portal takes over. In place is the default ⚑ — the themed page keeps the reader where they were; Portal's own notification is the alternative.
One-time code entry
Off▾
Off (default) · On, new in this pass ⚑. Ghost's magic-link email now carries a sign-in code as well as a link and the themed sent panel said only "check your email". At On the sent panel adds a code field and its own button, under the sentHeading text. ARCHITECT: member-form registry extension, and an endpoint to verify the code against ⚑ — no module in the registry verifies a code today. No-JS: the whole panel is absent and P0·4’s notice stands in the form’s place ⚑ — with no script there is no send, so there is no code to paste.
A signed-in member on this page
Membership summary▾
Membership summary · Send them to the account page. Never the signup form ⚑ — a member who lands on /signup/ has nothing to sign up for. This is the category’s member-state model, and the reason no design carries a Member visibility row ⚑.
Everything that changes a subscription
Ghost Portal🔒
Read-only. Plan changes, checkout, billing, email changes and newsletter preferences are Portal’s ⚑ — the theme draws the trigger and Portal draws the rest. This is the category’s boundary and no control moves it.
Member buttons are conditional ⚑ — every Sign up, Subscribe and paid-tier button is absent where the connected site cannot support it: self-signup switched off, members disabled, or no payment provider connected. Ghost seeds a $5 tier at install, so an unconnected site would otherwise ship a card whose checkout cannot complete. The rows stay in this panel, disabled, with the reason readable.Ghost’s own pop-up needs JavaScript ⚑ — every button that opens Portal, including every tier deep link and every hand-off on the account page: with JavaScript off, nothing happens. The theme cannot substitute anything for it, so the notice is the panel’s, not the page’s.Nothing identifying is printed ⚑, new in this pass — no member name, no member email, and no join date on any of the thirteen. Ghost gives a theme no join date and no list of a member’s newsletters, so both rows are gone: the newsletter row is a link out to Ghost’s own account screen, and the email row hands off the same way. Layout and actions are ours; anything that names the reader is Ghost’s account panel’s.
EDITING · THE P0 PRIMITIVESEvery authored string edits inline on canvas with the P0·1 toolbar — bold · italic · underline · link, its popover carrying Open in new tab and rel nofollow · noreferrer · sponsored: eyebrow, heading, blurb, ctaLabel, note, legal, benefits[], benefitsLabel and every state string. Ghost-owned content is never inline-editable ⚑ — the member's name and email, the tier name, the price, the renewal date, the newsletter names and a tier's description and benefits all answer "Edit in Ghost" or show P0·1's lock pill. Every URL field opens the Ghost-aware Link Picker, Portal actions first. No fixed English visitor-facing string ships: the rescued literals above are fields with defaults, and the badge vocabulary and sending word are catalog strings. There is no Preview control in this panel and there never was one to remove — states are P0·6's switcher, audiences are View as.benefits[] is the P0·3 authored list ⚑ — drag to reorder, per-row overflow with Duplicate and Remove, Add arrives with content rather than an empty shell, Remove is never disabled, and the range line reads 0–6 · 4 used. Add disables at six with its reason in a sentence. Per-item content only: a name and a detail edit inline, and no per-item layout control exists ⚑. Tiers are the other list and are Ghost’s — no Add, no Remove, no drag.The one icon slot is the primary button’s ⚑ — P0·2's button-icon rules: Before or After the label, always Small, always the label's colour, its Size and Colour rows hidden. The list marker is the second where a design draws ticks, and it is whole-list.Member Visibility lands nowhere in A30 ⚑, and it is a judgement rather than an omission: the route is the member state. A signed-in member never sees a signup form — the Data group's "A signed-in member on this page" decides what they see instead — so a section-level Everyone / Logged out / Free / Paid row would hide a page from readers the route has already sorted. P0·4’s member-aware action editor never opens here for the same reason. Recorded in the Reconciliation notes.

Nine controls of its own.This pass · nothing identifying, and two rows deleted. Member since is gone and so is the newsletter list ⚑ — Ghost’s member object carries neither a join date nor a theme-readable list of newsletters, so both rendered empty on every live site. The newsletter row is now a link out to Ghost’s own account screen, and no design prints a member’s own name or email: the head is the authored account heading, the email row hands off, and the avatar goes with the name it was derived from.This pass · the no-JavaScript notice. Ghost’s signup endpoint will not accept a plain form post ⚑ — tested on both live servers — so P0·4’s notice replaces the form rather than the form standing scriptless. Sending, sent, expired and invalid are Ghost’s own script and are unchanged.This pass · the signed-out account page. Ghost does not redirect an anonymous visitor away from /account/ ⚑, so the fourth account tile is a designed signed-out state: a heading, one sentence, a link to /signin/, and no member row at all.
