P0·3 · Item-list controls

The sidebar's Content group renders an authored list as rows: drag handle, label, per-row overflow, and an Add button at the foot. Selecting an item on canvas edits its content only — text, image, link. Per-item layout, spacing or emphasis does not exist: a design control writes one value on the whole section, by construction.

Ghost-sourced lists (posts, tags, authors, tiers) are not this. They show no Add or Remove — their controls are how many to show and in what order. Both are drawn side by side below so the difference stays visible.

The two grammars must never blur — an Add button on a Ghost-sourced list would imply Inflozo can create posts, and a drag handle would imply it can reorder the feed. The sourced card carries a "From Ghost" mark and a plain sentence saying where its items come from. Selecting an authored item on canvas edits content only: its text props inline, its image via the image slot, its link via the Link popover. Layout, spacing and emphasis are section-level controls that write one value across every item.

PART A · A5: ITEM COUNTS ARE A NUMBER PICKER EVERYWHERE — NO "THREE · FOUR · SIX" SEGMENTED ROWS, NO "TWO OR THREE" PAIRS · A DESIGN MAY CAP ITS OWN MAXIMUM AND MUST STATE THE REASON · LOCKED VALUES ARE DISABLED, WITH THE REASON VISIBLE ⚑ INTERPRETATION, FLAGGED: A5 GOVERNS HOW MANY ITEMS — POSTS, TIERS, LOGOS, STEPS, FIGURES · IT DOES NOT GOVERN HOW MANY COLUMNS OR HOW MANY PER ROW, WHICH ARE ARRANGEMENTS AND STAY NAMED SEGMENTED VALUES · LISTED AS AN OPEN QUESTION IN THE PATCH NOTES A DESIGN MAY ADVISE AT A COUNT ("AT THIS COUNT, 1 ROW READS BETTER") · ADVICE ONLY — PART A · A8 FORBIDS THE SWITCH

A fixed set of count buttons is a design's arithmetic imposed on a user's content. The picker lets any number be asked for; the design answers with its own ceiling and its own reasons, in sentences the user can read. Where a count was previously drawn as a segmented row, that row becomes a stepper in its category's own pass.
