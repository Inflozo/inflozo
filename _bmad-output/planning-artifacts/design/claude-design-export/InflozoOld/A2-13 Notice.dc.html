ARCHITECT: REGISTRY ADDITION (consent) · the upgrade path · not drawn
ARCHITECT: REGISTRY ADDITION (consent) A real consent surface needs what no registry module provides: choice storage (one stored answer with two values), a DOM event announcing the choice, and gating for owner-injected scripts via <script type="text/plain" data-consent> code-injection blocks activated on accept. That is the recorded upgrade path for this design — if the registry gains consent, the Accept/Decline drawing lives in this file's history. Until then the theme does not pretend: no module name is coined, and the bar ships as the informational Notice above. No-JS state, designed: the bar renders and stays; the close is hidden rather than inert (the dismiss sentence) — an honest degradation an unanswerable consent question could never have.
