## P0·1 Inline text toolbar

The floating toolbar that appears when the user selects text in any inline-editable text prop, headlines included (FR-D4). One row, five actions: **Bold · Italic · Underline · Link · Remove link**. Nothing else — no font, no size, no colour.

- The Link action opens the **Link popover**: the Ghost-aware Link Picker (internal pages / posts / tags / authors, live-searched · Portal actions: Sign up, Sign in, Account, Upgrade · external URL · email) plus, below the target, **"Open in new tab"** (checkbox) and a **Rel** row of three toggles: `nofollow` · `noreferrer` · `sponsored`. Editing an existing link re-opens the same popover pre-filled; Remove link strips the mark.
- Draw the toolbar over a headline and over body text; draw the link popover in both its search state and its filled state.
- A text prop bound to a Ghost Admin text setting is plain-text-locked: the toolbar never appears on it; state this.
- Specify keyboard access (⌘B/⌘I/⌘U/⌘K) and where the toolbar goes at 390.

## P0·2 Icon slot + Icon Picker

Icons exist only in **icon slots** — a user can never place an icon anywhere else. A slot is either filled (shows its icon) or empty (dashed 20 px placeholder visible only while the section is selected).

- Clicking a slot opens the **Icon Picker**: a searchable grid of the curated icon set, category chips (Arrows, Interface, Media, Commerce, Social/Brands…), recent row. The library is **Tabler Icons** (owner-ruled: one MIT set whose `brand-*` glyphs cover the social rows — the PRD's Lucide reference is amended, since Lucide 1.0 removed all brand icons). Draw the picker with Tabler's stroke style.
- A filled slot, when clicked while its section is selected, shows a **popover**: swap icon · **Size** Small/Medium/Large · **Colour** role Text/Muted/Accent/On-accent · Remove. Named values only.
- **Button icons:** when any button is selected, its popover offers an optional icon **Before / After** the label (icon slot rules apply). Draw a button with a leading icon and one with a trailing icon.
- Social icons are brand glyphs from the same picker's Social/Brands group; a design may render them icon-only, icon+full name, or icon+short form (Fb, X, Li, In, Yt) — that display choice is a per-section control where a category's issues call for it, not a picker feature.

## P0·3 Item-list controls

For sections whose repeating items the user authors (FAQ entries, stats, ticker messages, steps, gallery images, testimonials…):

- In the sidebar's Content group, the list renders as rows with a drag handle (reorder), a per-row overflow (Duplicate · Remove), and an **Add {item}** button at the foot. A newly added item carries sensible placeholder content, never an empty shell, and lands last.
- Selecting an item on canvas edits its **content only** — text, image, link. Never per-item layout, spacing or emphasis (a design control writes one value on the whole section, by construction).
- The list states its min/max ("2–6 messages") and what the design does at each end; at the max, Add disables with a short reason.
- Ghost-sourced lists (posts, tags, authors, tiers) are **not** this: they show no Add/Remove — their controls are how many to show and in what order. Draw one authored list and one Ghost-sourced list side by side so the difference is visible.
- Where a design shows fewer items than exist, the sidebar says "8 items · 3 shown in this design".

## P0·4 Member-aware action editor

For sign-in / subscribe / account actions in headers, footers and CTA rows:

- Per action, a compact three-state editor — **Logged out · Free member · Paid member** — each state carrying: **Show** (toggle) · **Label** (text) · **Link** (Link Picker, Portal actions first). Defaults: logged out shows "Sign in" (`signin`) and "Subscribe" (`signup`); members see "Account" (`account`); free members may see an upgrade ask (`account/plans`).
- This compiles to server-side member checks; nothing flashes client-side. The canvas previews it through the existing member-state toggle (Anonymous / Free / Paid).
- Distinct from the **Member visibility** control (Everyone / Logged out / Free / Paid) that CTA-bearing sections already carry — that hides a whole section; this edits one action. Show both in one frame so the difference is legible.

## P0·5 "Populate from…" data panel

One shared panel, reused by every section that can draw content from the user's Ghost site instead of authored content:

- **Source**: Static (authored) · From posts. "From posts" reveals: **Filter** Latest / Featured / By tag (tag select) / By author (author select) / Hand-picked (post search-and-pick list) · **Count** (stepper) · **Order** Newest/Oldest · per-design meta toggles (date · author · excerpt · reading time · tag chip).
- Design the panel once at sidebar width, with the tag-select, author-select and hand-picked states drawn.
- Constraints to state in the spec: Count caps at 100; no relative-date filters (that vocabulary belongs to routes, not sections); a secondary feed renders nothing at zero items — heading and container together.

## P0·6 Editor state switcher

Several categories draw states that never show at rest, so their copy is blind sidebar fields today: form states (sent / invalid / failed / expired / subscribed — A16, A22, A30), the paywall's four gates (A32), the error pages' three copy sets (A31), search's query states (no query / results / no matches — A23), and scroll-triggered bars (A24's sticky, A27's carousel). Design ONE editor affordance for all of them:

- A small **state switcher in the canvas chrome**, beside the existing member-state toggle (Anonymous / Free / Paid) — never a sidebar control, and never a per-section "Preview" control. Its options are contextual: it lists the states the selected section actually has.
- Switching states re-renders the section in that state so its copy is editable inline in place.
- Draw it on a subscribe form (Empty · Invalid · Done · Subscribed) and on the paywall (Free signup · Paid · Upgrade · Named tier).
- Include a "simulate scroll" entry for scroll-triggered elements (a sticky bar's condensed state) so those are designable too.

## P0·7 Editor Cards screen (new screen: S14)

Ghost's post editor writes **Koenig cards** into every post body — image, gallery, video, audio, file, product, bookmark, button, callout, toggle, header, signup, CTA, code, blockquote, divider and the rest. Their styling on the live site is the theme's job, so Inflozo must let the user design them — once per project, not per post.

- Add **"Editor cards"** to the S4 editor's left navigation (with Pages/Layers where the current design puts surface links; also reachable from Theme Settings).
- The screen: a **card-type dropdown at the top** (exactly like the Page/template switcher pattern in S4) listing every Koenig card with a "customised" badge where the user changed one; the canvas below renders that card inside the style-guide post fixture at reading width, live in the project's Style Pack.
- Right sidebar: that card's own panel — **4–7 controls, named values only** (e.g. callout: background role, radius, emoji show/hide; bookmark: layout, thumbnail on/off, border) — plus **"Reset to Ghost default"** per card.
- **Colour controls are never offered for header, signup and CTA cards** — the post author sets their colours inline in Ghost's editor, and a control that silently loses to an inline style is worse than none. Say this on the frame.
- The A33 card **treatments** (the six whole-set styles) are chosen on this same screen, above the per-card dropdown: one treatment active per project, then per-card overrides on top.
- Draw: the screen with the dropdown open · a callout card selected with its panel · the reset confirm.

## P0·8 Library-wide rules (state in the spec; no frames needed)

1. **Remove every "Preview" control** from every control panel in the library — previewing is the editor's global Preview toggle, never a sidebar control.
2. The 4–7-controls norm is lifted where this pass adds controls: the ceiling is the PRD's **≈15 visible controls per design** (+3 universal + the Data group); Quick Controls stay the 3–5 highest-impact.
3. Named values only, everywhere — never px, hex or free CSS.
4. Any new behaviour must name a module from the fixed registry (`marquee`, `rotator`, `dismiss`, `mode-toggle`, `search-overlay`, `price-toggle`, `member-form`, `lightbox`, `countdown`, `count-up`, `accordion`, `tabs`, `carousel`, `share`, `filter-strip`…). If an instruction needs behaviour no module covers, mark it **"ARCHITECT: registry addition"** on the frame and in the spec and design the no-JS state — never invent a module name.

Finish with a component inventory (name · what it is · where first established) so the category patches can cite it.
