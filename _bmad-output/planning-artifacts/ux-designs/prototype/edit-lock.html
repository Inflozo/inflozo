The holder — a popover, not a modal

The holder is mid-sentence. It states the sync position before asking. The countdown is a no-response timer and it restarts the instant the holder interacts with the popover at all, focus included — it only runs out when nobody is there. Announced assertively.

One deviation from B5c, and it is not optional

The frame itemises the loss per section — “Home hero — design and two controls · Footer — three link labels · Post template — measure”. That detail does not exist. The heartbeat carries unsynced_edits and nothing else; the requester’s browser has never seen the holder’s journal. The modal keeps its shape, its danger fill and its “Or message Rosa” escape, and its body becomes: “7 unsynced edits will be lost. They exist only in Rosa’s browser. We cannot retrieve them from here.” Also: B5c says “changes”; §AD2 says edits is canonical, everywhere.

Deploy and export from a read-only session

Ship it or Export first prompts a take-over, surfacing “X unsaved edits exist elsewhere” — so a stale cloud snapshot can never silently ship. Drawn on no frame; it is added to B5’s family.

Not drawnNo prompt owns this state; it is a state of a drawn surface, and step 6 draws it from that surface’s frame and DESIGN.md’s component rules.

Nothing is drawn here on purpose. A picture invented in this file would be a second interface vocabulary beside the export’s, which is the one thing R-74 forbids. What it must show is described below.
