Four corrections, and one of them is the surface&rsquo;s own primary value

1 · posts_per_page is missing entirely. It is FR-Q1’s first field and belongs at the top — every surface in the product that mentions posts per page links here, never into Ghost Admin, because Ghost has no such setting (ruling R-10 #13). 2 · The logo row loses its Replace button. Ghost’s logo is read, never written (AD-10’s allowlist) — padlock it like the title, with a link out. 3 · The dark row is drawing the wrong thing. “Follows the reader’s system setting” is the visitor’s moon toggle; this row is FR-D7’s project mode — Light only / Light + Dark — plus a “Clear dark overrides” row. 4 · The meter reads 3 of 20 and should read 3 of 17: three of Ghost’s twenty slots are the dark built-ins every Inflozo project declares (FR-Q2).

And four additions to the builder

The Ghost Admin group, a visibility condition, FR-Q3’s text-prop confirm (“Ghost’s own settings are plain text, so the marks come off”), the post-deploy key-immutability notice, and the pack-switch warning on a promoted accent. All prompt A6.

B18&rsquo;s keys are the wrong shape

The frame draws flat keys — subscribe, read_more. FR-Q6 makes them dotted namespace.name — member.signup_cta, post.reading_time, archive.empty_heading — because a flat catalogue collides the moment two surfaces both want “subscribe”. FR-Q8 adds a brace-refusal error state: a malformed interpolation token is a whole-site 500. The RTL acknowledgement is right, and FR-Q6 requires it repeated as a pre-deploy warning on the Pre-flight Check.
