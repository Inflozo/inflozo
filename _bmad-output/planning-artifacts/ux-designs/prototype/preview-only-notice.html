One word on it was wrong

B15 said upgrade to Ghost(Pro) Creator. Ghost’s 2026 lineup is Starter / Publisher / Business, so it is Publisher or higher — the frame says so since A9 item 10 — read at ghost.org/pricing on 2026-09-03, a page read and not an executed probe, so VERIFY-AT-BUILD item 1 stays ⛔ until the Starter trial. Everything else on this frame is right, and S8a′ and S11a now match it.

Probed, never asked

At connect, hostSettings.limits.customThemes is read. It is a theme-name allowlist, not a yes/no flag: @tryghost/limit-service declares customThemes as an allowlist limit and the upload endpoint asks errorIfWouldGoOverLimit('customThemes', {value: themeName}) (read in source, Ghost 6.54.1 core/server/api/endpoints/themes.js). Its absence means self-hosted — GET /admin/config/ carries no hostSettings key on 5.130.6 or 6.58.0 (executed, MEASUREMENTS §15h). The Ghost(Pro) half is still ⛔ — VERIFY-AT-BUILD item 2, blocked on a Starter trial — so the probe must test Inflozo’s frozen theme name against the list, and “present” is not the same as “blocked”. There is no user-declared-plan step in the happy path and no plan field in Manage Keys. FR-C5’s daily health check re-runs the probe, so the flag sets and clears without any user action — clearing is not the user’s job — and a successful deploy clears it too. The one path with a question is the unreadable-hostSettings case.
