Two sentences on that frame were wrong and both were load-bearing

“It happens on every deploy” — it is the first upload to a site, deploy-only included, because manual activation in Ghost Admin must not bypass the safety net. “Snapshots count towards your history — Free keeps 3, Pro keeps 10” — the snapshot is exempt from the history limit and never prunes. Both corrected in the 2026-09-04 export (A7 item 2): the first sentence is gone and the second reads “Kept outside your version limit.”

B12b’s reason was the most expensive error in the export

It said “your integration key may not have theme read permission … Check the key.” Ghost’s admin-API allowlist (tokenPermissionCheck in core/server/web/api/endpoints/admin/middleware.js, read in 6.54.1) lets a Custom Integration token reach themes only as POST and PUT, so every GET /themes/* made with an Admin API key is refused on every host — 403 on Ghost 6 and 501 on Ghost 5 (executed, MEASUREMENTS §15h and §21m; AD-24 must fold both into one Inflozo code). There is no key to fix. Telling a user to go and fix one sends them to spend an afternoon on something that cannot be done. The replacement names the real cause (no Staff Access Token), then what protects them anyway — Ghost keeps the pre-Inflozo theme under Settings → Design, which holds because this gate fires only at the first upload; later Inflozo versions replace each other under the frozen name (FR-J10) and live only in Inflozo’s history — then three real actions. Corrected in the 2026-09-04 export (A7 item 2): the body names the token and says there is no permission to switch on, shows the executed 403 (the Ghost 6 answer — Ghost 5’s is 501, and AD-24 folds both), and the buttons are Add the token · Deploy without a snapshot · Cancel; “Check the key” is gone. One thing to execute at the story: the reassurance now prints a Ghost Admin path, Settings → Design, which this build has not verified on 6.58.0 (T1 exists for that); the backup gate’s rule is to describe what to look for rather than print a path.
