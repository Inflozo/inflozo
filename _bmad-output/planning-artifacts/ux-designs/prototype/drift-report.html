Drift Report

Before every deploy after the first to a given site, Inflozo reads the live theme and compares it against what it last deployed there. If anything differs, the deploy stops. Rows are grouped Changed / Added / Removed and — critically — each is named by the user’s own layer name ("Home hero", "Three Column footer") with the raw filename only as small mono text beneath. Never a raw path as the primary label. Two actions: Download the live theme first (offered before the destructive one) and Overwrite and ship anyway — ink, not danger, because it is a deliberate choice.

Not drawnThis surface has no frame in the export. Appendix A prompt A3 (frames D3a, D3b, D3c) will draw it; it has not been run.

Nothing is drawn here on purpose. A picture invented in this file would be a second interface vocabulary beside the export’s, which is the one thing R-74 forbids. What the prompt must produce is described below and in EXPERIENCE.md Appendix A.

It fails open, and it never asserts drift without two manifests

Where the Staff Access Token is absent it cannot read the live theme, so it shows a single sky information row inside the pre-flight list — “Couldn’t check whether your live theme changed … Shipping anyway” — and the deploy continues. A layer rename produces no drift at all, so the list never shows one: nothing on the live site changed, only a filename Inflozo chose.
