Where to start

  • Understand the system — the plain-English architecture, then the spine for the rules.
  • Build something — the spine, then the schema, then the PRD section for that area.
  • Check a claim about Ghost — the mechanical verification files, then the research companions. Both outrank the PRD body.
  • Find what was already tested — the measurements file. Every section carries the command and its output.
  • Know what is still unverified — the external-facts register.

The pre-deploy backup gate

_bmad-output/planning-artifacts/architecture/.../BACKUP-GATE.md

Inflozo is not a backup tool. Before the first deploy to a site the customer is blocked until they confirm they hold their own backup, with a checkbox per item and the exact Ghost menu path for each. The security gate

_bmad-output/planning-artifacts/architecture/.../RLS-TEST.sql

E1's exit criterion and the acceptance test for a restore. 70 assertions, and it ABORTS on failure — it used to print FAIL and exit 0, which is why six holes survived three rounds. Mutation-tested: reverting any fix turns it red. Pure SQL, so it runs in psql or the Supabase dashboard editor.
