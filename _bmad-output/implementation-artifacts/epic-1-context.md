# Epic 1 Context: Foundations & Design System

## Goal

Stand up everything every later epic lands inside: the monorepo with its pure/shell package split, CI/CD to production Vercel on both production domains, the whole schema with row-level security proven by a gate, tokens and components lifted from the Claude Design export, magic-link sign-in over Resend, and a dashboard where a signed-in user can create, rename, duplicate and delete projects. Exit: sign in on production; the dashboard exactly as cut below; RLS verified on every table the schema story creates. **Stories 1.1, 1.2 and 1.3 are done**; 1.4 and 1.5 remain.

## Stories

- Story 1.1: The repository, the package split and CI/CD to production — done
- Story 1.2: The whole data model and its row-level security — done
- Story 1.3: Design tokens and the app component kit, taken from the export — done

## Requirements & Constraints

- Sign-in is magic link only: Supabase Auth email OTP link on a branded template, routed through Resend SMTP. No password field exists anywhere. Sessions persist 30 days rolling. This epic owns the magic-link and email-change-verification emails, two of the product's six.
- Dashboard cut line. IN: the authenticated shell (top bar, account menu, navigation); project cards with name, updated-at and a static placeholder derived from the project's Style Pack tokens (never a captured thumbnail); create blank, rename, duplicate, delete behind type-the-name confirm; the plan cap at creation (Free 1 project, Pro 25) with a contextual upgrade prompt; one linked site per project, and an unlinked project renders the bundled sample dataset. OUT, for later epics: linked-site badges, deploy-status chips, the other three creation paths, the connected-sites strip, asset quota meter, changelog popover, notifications bell.
- Security floor: RLS on every table keyed to `auth.uid()`; secrets never in `NEXT_PUBLIC_*`; CSP with no `'unsafe-eval'` and `frame-ancestors 'self'`, `connect-src` composed per session — a nonce policy on the app host, a static one on marketing. **The CSP is not built yet**: it arrives with the first story that has a page to protect (1.4); `tools/probe/csp/proxy.ts` is its executed shape.
- Zero axe-core violations at WCAG 2.1 AA on every app surface; one focus ring everywhere; reduced motion honoured. No analytics or telemetry in the app; Sentry on app and server; logs carry no user content or credentials.

## Technical Decisions

- **Hosting shape, as built.** Next.js 16 App Router on Vercel Pro. One deployment, host-routed in `apps/web/proxy.ts` (Next 16's rename of `middleware.ts`, Node runtime; the pure decision is `routing.ts`, tested with `node --test`). `inflozo.com` serves `app/(marketing)/`; `app.inflozo.com` is rewritten onto the internal `/app` prefix, so app routes live under `app/(app)/app/` and `(app)` is the route group that will carry the authenticated layout. `/app` never appears in a public URL; on `localhost:3000` it is reached directly. The apex is canonical; `www.inflozo.com` 308-redirects to it. **All three domains serve the deployment today (200 / 200 / 308)** — the pre-1.1 404s are history. Supabase supplies Postgres 17, Auth, Storage and Vault; Resend sends every email; Dodo sits behind a swappable adapter in `server/billing/`.
- **Publishing runs from GitHub Actions, not on the push** (owner, 2026-09-05, DW-7). `ci.yml` has three jobs: `check` (`pnpm check` + `pnpm build`), `rls` (the database gate) and `deploy` (`vercel pull/build/deploy --prebuilt --prod`) with `needs: [check, rls]`; `apps/web/vercel.json` sets `git.deploymentEnabled.main = false`. A red gate publishes nothing — proved by control. The three Vercel secrets live in the repository's Actions secrets as well as `tools/probe/.env`.
- **Package split (pnpm workspaces, no Turborepo).** `packages/library` (data only) → pure core `packages/section-runtime`, `packages/ghost-shim`, `packages/theme-compiler` → shell `apps/web`, the only deployable; a lint rule fails the build when a core package imports Next.js, Supabase, Node or the shell. Packages are `@inflozo/*`. Tailwind 4 styles `apps/web` only — `globals.css` carries `@source not "../../../packages/library"`. Tests are `node --test` on erasable-syntax TypeScript, no framework. **Two loose ends the next importing story closes (DW-1, DW-2):** `packages/library` declares no entry point, and `apps/web` does not yet depend on the core packages, so `transpilePackages` is inert — the first story that imports across the boundary (1.3 for the library) decides the entry shape and adds the `workspace:*` dependency.
- **Pinned versions are the installed versions**: Node 24, TypeScript 7.0.2 strict (the root also holds `typescript@6.0.3` only because `typescript-eslint` refuses to load against 7 — it ships nothing), Next 16.3.1, React and React DOM 19.2.8 pinned together, pnpm 11.22.0, Tailwind 4, supabase-js 2.115.0 with `@supabase/ssr` 0.12.6 (Story 1.4 moved the pair — `ssr`'s peer is `^2.114.0`), zod 4.4.3, `gscan` 6.4.2, `handlebars` 4.7.9 dev-only and never shipped, `resend` 6.20.0, `dodopayments` 2.47.0.
- **Schema and RLS, as built.** The whole model is live on the hosted Supabase project the deployed app reads (identity confirmed against Vercel's env), and the live database starts at zero users. Every RLS table denormalises `user_id`, every policy is `user_id = (select auth.uid())` in the hoisted form, every project-child table also carries a restrictive `owns_project(project_id)` policy, and every RLS table has an index whose first key is `user_id`. Server-only tables (`site_credentials`, `billing_events`, `credential_audit`) live in a `private` schema PostgREST never exposes, RLS on with zero policies. Server-asserted tables (`deploys`, `entitlements`, `subscriptions`, `site_snapshots` and their kin) are select-only to `authenticated` on both INSERT and UPDATE with full grants to `service_role` — asserted as a class derived from the catalogue. Immutable columns are frozen by `BEFORE UPDATE` triggers that hold against the service role.
- **How the schema changes from here** (owner, 2026-09-05). `supabase/migrations/20260904120000_complete_schema.sql` is **frozen** — it has been applied to the live database. Every later change is a **new file** in `supabase/migrations/`, applied to Test first, and the architecture's `SCHEMA.sql` keeps growing as the cumulative readable picture; both must change in the same commit, with the new table's policy and its assertion in `RLS-TEST.sql`. The gate, `bash supabase/tests/run-rls-gate.sh` (also CI's `rls` job), applies every migration in filename order to one container database and `SCHEMA.sql` to another and **diffs the two schemas** — equivalence, not byte equality. `supabase/tests/rls.sql` and `prelude.sql` remain byte-identical copies of the architecture's `RLS-TEST.sql` and `PRELUDE.sql` and the gate refuses to run if they drift: change the architecture original, then re-copy. Never apply `PRELUDE.sql` to hosted Supabase — its `auth.uid()` stand-in returns NULL and would silently disable every policy.
- **Writing an RLS assertion.** Failure is `raise exception`, never `raise notice`; a catalogue check raises on a non-empty result; a `when others` handler must re-raise the block's own `FAIL` sentinel (21 assertions once reported a real hole as PASS); a class assertion derives its members from the catalogue and is mutation-tested. `PRELUDE.sql` now models hosted Storage's refusal of direct `delete from storage.objects` (escape hatch `set storage.allow_delete_query = 'true'`), read from the hosted catalogue.
- **Reaching the hosted database for verification:** its host is IPv6-only, so a `psql` container needs `--network host`, and this machine's DNS stub fails intermittently — confirm with `dig +short @1.1.1.1` before reading an outage.
- **Conventions.** snake_case plural tables, `{table}_id` keys, Postgres enums, uuid v4 defaulted server-side, `timestamptz` UTC; one zod schema per boundary; error envelope `{ code, message, detail?, action? }`; mutation is client → server action → service-role write. Feature flags are rows in `feature_flags` (two seeded), never env vars.
- **`notifications` exists** so later epics write to it before any reader; `data` and `link` carry a per-`kind` shape validated on write. **Plan state** comes from one server-side `resolveEntitlement(userId)` with the plan table expressed once as data; an absent row resolves to `free`; a `profiles` row and an `entitlements` row are created at signup by the two `auth.users` triggers already live. The dashboard cap check calls the resolver.

## UX & Interaction Patterns

- **The design export is the design authority (R-74).** Never edit `_bmad-output/planning-artifacts/design/claude-design-export/`. Tokens, type scale, spacing and colour roles come from `Calibration Set.dc.html`; every control, panel, badge and state from `Editor Sidebar Kit.dc.html`; the greyed-with-reason pattern from `P0-0 Greyed Control Pattern.dc.html`. The frames carry their values as inline styles, not CSS variables; `DESIGN.md`'s front matter is the **named transcription** (`{colors.*}`, `{typography.*}`, `{rounded.*}`, `{spacing.*}`, `{elevation.*}`, `{components.*}`) and those are the names the token layer uses — where it and the export disagree, the export is right and `DESIGN.md` is the bug. A surface with no frame is extrapolated from the nearest one that has; never invent a component. Every story with a screen names its frame and carries a "matches the frame" criterion.
- **Two token rules re-derived on 2026-09-04 and easy to get wrong from older frames:** keyboard focus is one solid 2px `{colors.coral-text}` ring everywhere (the 40% coral wash is hover and selection only), and placeholder, hint and mono line-number text is `{colors.ink-soft-aa}`, never faint ink. Coral has two values: `{colors.coral}` for fills, outlines and carets; `{colors.coral-text}` wherever coral carries text or sits under white type. One coral action per surface; marigold only for Pro and celebration.
- **Three things Story 1.3's spec must flag under `## Questions for the owner` rather than resolve**, because the epic's acceptance criteria and the UX spines disagree: (1) the epic asks the gallery to render every component "in light and dark", while `DESIGN.md` says there is no app dark mode in v1 — dark chrome exists only inside the canvas and on the template-surface canvases in `{colors.ink-deep}`; (2) the epic names `R Responsive System.dc.html` as the collapse ladder, while `EXPERIENCE.md` says that file governs the *sections'* archetypes, and the app's own below-1440 behaviour is drawn in `D8 Editor Below 1440.dc.html` (Layers to an icon rail, Controls to an overlay); (3) the `*-kit.js` files in the export are section-category render kits over Style Pack tokens, not app-chrome kits — the pattern to reuse is "one block rendered from a token object", not their code.
- Frames: Sign In is `S1 Sign In.dc.html` S1a (1440 and 390), S1b, S1c (S1c draws the page behind the OS passkey sheet and nothing of the sheet). Dashboard is `S3 Dashboard.dc.html` S3a, S3b empty, S3c Free, S3d account menu (desktop popover and mobile dropdown); the New Project sheet and the Free-at-cap state are `D4 Dashboard Sheets and Blocks.dc.html` D4a and D4b.
- Magic Link Sent echoes the typed address, states 15-minute validity, counts down to resend without blocking anything, and always offers "Use a different email".
- Every empty state is designed: the empty dashboard is "Every great site starts somewhere. Yours starts with hundreds of gorgeous sections." plus New project; loading is skeleton cards, never a spinner. Typed confirm only for project and account delete, with no wit on those surfaces, and an irreversible confirm opens with focus on the cancelling action.
- A greyed control shows its reason as one sentence in the helper-caption slot, never a tooltip; a control that could never act here is absent and the panel says why.
- Widths 1440 / 834 / 390; Sign In and Dashboard fully usable at 390. Read font sizes off the frame (half steps like 12.5 and 11.5 are common), never round to a scale step. Fonts are Bricolage Grotesque (display), Inter (UI), JetBrains Mono (mono: URLs, keys, chips, any number that changes in place). Icons are drawn inline; the app's are the frames' own paths, and Tabler (D1) is the sections library's set, not the chrome's (R-92, 2026-09-05). The Pro badge is ✦ plus the word "Pro"; plan limits are shown, never implied; library size is "hundreds of gorgeous sections", never a number.

- 1.2 before 1.4 and 1.5 (`profiles`, `entitlements`, `projects`, `notifications` — all live). 1.3 before 1.4 and 1.5 — both screens are built from the kit; 1.3 ships an internal component gallery route, not a product screen, and is the first story to import `@inflozo/library` (DW-1, DW-2). 1.4 before 1.5. 1.4 also brings the CSP in `proxy.ts` and the authenticated layout under `app/(app)/`.

- Process rulings binding every story: commit and push to `main` after every phase with the one-line message `Story 1.<n> - <Phase> - <one line about the story>`; `python3 tools/doc-audit.py --check` before every commit, never pushed red; a story that adds a migration also updates `SCHEMA.sql` and `RLS-TEST.sql` and re-copies `rls.sql`; every UI story carries `## Owner's manual test` with URLs on the production domains, never a `vercel.app` preview; owner questions go under `## Questions for the owner` in plain English with an example, numbered options and a (RECOMMENDED) mark; BMAD stays on 6.11.0.
